# 탈출 성공 선택 및 연속 점수 구현

- 라우팅: `escape-zombie-school` / `levelmini` / `t_929fe175`.
- 탈출 흡입 완료는 `clearStage()`로 같은 스테이지의 `cleared` 선택 지점에 머문다. 이후 스토리 진행도 이 결정 지점에서 연결할 수 있다.
- `escapeResult`: `{stageId, stageScore, totalScore, timeMs, totalTimeMs}`. 클리어 중복 호출은 무시한다.
- `continueToNextStage()`는 결과 화면에서만 실행되며 이전 확정 총점/시간을 다음 스테이지에 전달한다. HP·무기·레벨은 기존 새 스테이지 규칙을 유지한다.
- 일반 `resetGame()`은 누적 점수/시간을 0으로 되돌린다. 마지막 스테이지에는 다음 진행이 없다.
- 글로벌 랭킹은 누적 점수/시간, 스테이지 랭킹은 해당 스테이지 점수/시간을 기록한다. 저장 엔트리와 Firebase 규칙은 그대로다. 체크포인트·재시도에 누적 메타데이터를 전달한다.
- Firebase 준비 여부가 결과 표시나 점수 계산을 막지 않는다. 저장 불가 상태는 기존 제출 경고로 남긴다. 실제 Firebase 데이터 쓰기를 수행하는 테스트는 하지 않았다.
- 집중 검증: 연속 두 스테이지 클리어·사망·새 시작·중복 선택·최종 스테이지·실제 포탈 프레임 완료·랭킹 버킷 분리. 단위 검증은 메모리 테스트 클라이언트만 사용한다.
- 빠르게 다음 스테이지로 진행했을 때 이전 제출 응답이 나중에 도착해도 최신 제출 상태를 덮어쓰지 않도록 현재 pending 객체가 같은 요청인지 확인한다. 오래된 성공/실패 두 경우를 검사했다.
