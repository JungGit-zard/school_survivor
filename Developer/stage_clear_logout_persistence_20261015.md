# Stage clear logout persistence

- 담당: levelmini Worker. 범위: 진행도 저장 및 로그아웃 전 저장 완료 연계.
- 원인: clearStage가 만든 메모리 진행도의 저장은 비동기 큐로 실행된다. 로그아웃이 먼저 인증과 runtime을 비우면 대기 중 저장이 취소되어 재로그인 시 이전 stage1Clears를 읽는다. 같은 계정의 늦은 hydrate도 새 진행도를 이전 읽기 결과로 덮을 수 있었다.
- 수정: 로그아웃 직전 큐를 통해 최신 전체 Firebase snapshot 저장을 기다린다. 실패하면 인증 세션/진행도를 보존하고 기존 저장 실패 안내를 표시한다. 읽기 대기 중 runtime이 갱신되었다면 늦은 hydrate 결과/오류가 이를 덮지 않는다.
- 저장 구조, 로그인 방식, 그래픽, 실제 사용자 Firebase 데이터는 변경하지 않았다.
- 실제 대상 OAuth 및 재진입 확인은 별도 검증 게이트다. mock 통과를 실제 로그인 또는 배포 완료로 보고하지 않는다.

- 2026년 10월 16일 마무리: 저장 대기 중 변경이 생기면 최신 전체 snapshot을 다시 저장하며, 계정이 바뀌면 다른 계정의 로그아웃을 진행하지 않는다. 저장 실패 시 설정창을 유지하고 한국어·영어·일본어 안내를 표시한다. 타이틀이나 인증 제공자 방식은 변경하지 않았다.
