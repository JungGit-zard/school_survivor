# R3F Survivor 최적화 구현 기록 - 2026-07-26

## 적용 범위

- `weaponTargeting`은 `enemySimulation`의 공유 공간 격자와 overflow/fallback 경로를 재사용한다. 범위 공격(splash)의 후보 수집도 전체 적을 반복하지 않는 O(N) 경로로 정리했다. 넓은 반경의 거리순 수집은 고정 최대 힙과 제자리 heapsort를 사용해 O(N log N)이며 호출당 할당이 없고, 거리·동점 순서를 보존한다.
- 매 프레임 Zustand에 쓰던 `elapsedMs` 갱신은 변경 가능한 `gameRuntimeTime`으로 분리했다. HUD에 표시할 값만 최대 초당 10회 발행하며, 게임의 시간 판정은 정확한 런타임 시간을 사용한다.
- 풀링된 좀비와 투사체는 보수적인 화면 경계 수동 컬링을 사용한다. 실제로 그릴 인스턴스 수는 `mesh.count`로 압축한다.
- 좀비는 near/mid/far LOD(거리에 따라 표현량을 줄이는 단계)를 적용한다. 단계별 파츠, 애니메이션, HP 바만 줄이고 toon 재질과 외곽선은 유지한다.
- AI 시야 검사는 2/4/8/12 프레임 간격으로 분산한다. 물리와 이동 계산은 그대로 유지한다.

## 반드시 지켜야 할 불변조건

- 적 선택, 피해 판정, 물리, 이동, 무기 규칙과 정확한 게임 시간 판정은 최적화 때문에 바뀌면 안 된다.
- 화면 밖 컬링은 보수적으로 처리한다. 화면에 보여야 할 대상이 잘리면 안 된다.
- LOD는 표현 비용만 낮춘다. 캐릭터/좀비의 toon 스타일과 외곽선은 모든 단계에서 남긴다.
- Firebase, Firebase Authentication, Graphics Studio 입력값과 저장 구조는 이 작업의 대상이 아니다. 데이터 테스트나 변경도 하지 않았다.

## 검증 근거

- 200명 적 상황에서 최적화 전후 타깃팅 회귀 비교 테스트를 추가해 결과 보존을 확인했다.
- 200명 넓은 반경 정렬 비교 수는 4,000회 미만이며, 거리·동점 순서 보존과 호출당 할당 없음을 확인했다.
- 집중 테스트 98개가 통과했다.
- 전체 테스트는 156개 파일, 1,351개 테스트가 통과했다.
- 프로덕션 빌드와 B02 게이트가 통과했다.
- 로컬 브라우저 E2E에서 Stage 1 시작부터 전투(00:02), 레벨업(00:16)까지 확인했다. 좀비 3D toon, 검은 외곽선, HP 바가 정상 표시됐고 브라우저 console warning/error는 0건이었다.
- 이 E2E 중 Firebase/Graphics Studio 저장을 조작하지 않았다.

## 남은 확인

- 실제 목표 기기에서 장시간 플레이하며 FPS, 프레임 시간, 메모리, 화면 경계 스트레스 상황을 계측해야 한다.
- 이 기록은 코드·로컬 브라우저 검증 결과다. 실기기 성능 수치나 모든 LOD 거리에서의 육안 품질을 이미 통과한 것으로 의미하지 않는다.
