## 2. 항목 1 — 성장폭 2.0x 적정성 → **CONCERN**

### 2.1 먼저 사실관계 정정: 실제 만렙 성장폭은 원래도 1.31~1.61x가 아니었다

커밋 메시지 "Maxing a weapon bought 1.31~1.61x"는 **levelmini의 측정 규약(서로 다른 카드를 한 장씩)** 기준 수치다.
게임은 `isUpgradeAvailable`(upgrades.js:238)에서 `kind: 'damage'` 카드에 cap을 두지 않으므로 **같은 데미지 카드를 반복 획득할 수 있다.**
실제로 플레이어가 할 수 있는 최대 성장(데미지 카드만 계속 뽑기)을 측정하면:

| | 최소 | 최대 | 중앙값 |
|---|---|---|---|
| 변경 전 | 1.59x (lineDraw) | 3.00x (umbrellaGuard) | **≈2.33x** |
| 변경 후 | 2.28x (lineDraw) | 3.00x (pencil·guided·shark·umbrella·eraser) | **≈2.76x** |

(측정 B. 전/후 모두 **신 추정기**로 재서 추정기 정정분을 제거했다.)

즉 만렙 성장폭의 실제 변화는 **1.4x → 2.0x(+43%)가 아니라 2.33x → 2.76x(+18%)** 다.
levelmini 문서 2절 각주에도 같은 취지가 적혀 있으나, 커밋 메시지 헤드라인과 핸드오프 요약에는 반영돼 있지 않다.

### 2.2 뱀서라이크 기준으로 2.0x(실측 2.76x)는 충분한가 — 이 게임에서는 **질문 자체가 구속조건이 아니다**

`xpCurve.js:22`에 기록된 12시드 실측: **240초 최종 플레이어 레벨 = 스1 6.50 / 스2 7.92 / 스3 7.00 / 스4 5.58.**
= 한 판당 **업그레이드 선택 4.6~6.9회**.

`MAX_WEAPON_LEVEL`은 5이므로 무기 하나를 만렙까지 올리려면 그 무기에만 4회를 써야 한다.
`MAX_OWNED_WEAPONS`는 8이고 획득(acquire) 카드도 같은 선택 예산을 먹는다.
**한 판에서 무기 하나를 Lv5까지 올리는 건 사실상 불가능하고, 현실 도달선은 Lv2~Lv3다.**

몬테카를로(측정 A, 그리디 정책, 스타터 계정, 3000판) 기준 실제 도달 상태:

```
pick 1  OLD med 19.84 → NEW med 19.84   x1.000
pick 2  OLD med 28.15 → NEW med 28.15   x1.000
pick 3  OLD med 31.20 → NEW med 32.60   x1.045
pick 4  OLD med 37.70 → NEW med 39.27   x1.042
pick 5  OLD med 42.48 → NEW med 44.58   x1.049
pick 6  OLD med 47.86 → NEW med 50.39   x1.053
pick 7  OLD med 54.64 → NEW med 57.97   x1.061   ← 240초 현실 종단
...
pick12  OLD med 71.86 → NEW med 81.21   x1.130
```

**240초 런의 현실 구간(pick 5~7)에서 이 커밋의 총 화력 변화는 +4.9~6.1%다.** 만렙 로드아웃 +44%와는 다른 세계의 숫자다.

### 2.3 그러면 이 커밋의 실제 성과는 무엇인가 — **첫 레벨업 체감의 균일화**다. 이건 명백히 좋다

데미지 카드 1장을 뽑았을 때의 Lv1→Lv2 증가율(측정 B):

| | 최소 | 최대 | 중앙값 |
|---|---|---|---|
| 변경 전 | **+0%** (studentLantern·chibiko — 데미지 카드 자체가 없었음), +15% (lineDraw) | +50% | +31% |
| 변경 후 | +32% (lineDraw) | +50% | **+44%** |

**"데미지 카드를 뽑았는데 체감이 없다"가 사라졌다.** 편차가 0~50%에서 32~50%로 좁혀진 것이 이 커밋의 진짜 값어치다.

### 2.4 CONCERN 사유와 권고

판정을 CONCERN으로 두는 이유는 2.0x가 틀려서가 아니라, **이 레버가 구속조건이 아니기 때문**이다.
"레벨업이 레벨업답게 느껴지게" 하려고 만렙 배율을 조정했는데, 플레이어는 만렙에 닿지 못한다.

권고(우선순위 순, 전부 이번 커밋 범위 밖 — 별건):

1. **`MAX_WEAPON_LEVEL` 5를 3으로 낮추는 것을 검토하라.** 현재 Lv4·Lv5는 240초 런에서 도달자가 거의 없는
   dead 구간이고, 그 구간을 위해 카드 18장을 추가한 셈이다. 3으로 낮추면 데미지 카드 2장이 곧 만렙이 되어
   "2장 = 2.0x"라는 이번 설계가 그대로 도달 가능해진다.
2. 위를 안 할 거면 **XP 곡선을 손대는 쪽**이 만렙 배율보다 레버가 크다. 다만 `xpCurve.js`는 2026-08-08에
   초반 스노볼 제거로 이미 조정된 상태라, 지금 건드리면 그 작업을 되돌린다. **권장하지 않는다.**
3. 만렙 배율을 더 올리는 방향은 **권장하지 않는다** — 도달자가 없어 체감이 0인데 마틸다 HP만 부풀린다.

## 3. 항목 2 — 스테이지 1~4 클리어 가능성 회귀 → **PASS**

### 3.1 마틸다 HP +44%는 클리어 난이도를 전혀 올리지 않는다 (전제 정정)

핸드오프는 "무기가 세졌지만 마틸다 HP도 +44% 올랐다"를 상쇄 관계로 제시했는데, **코드상 상쇄가 아니라 무관하다.**

- `stageConfig.js:13` `MATILDA_SPAWN_SEC = 230`, `durationSec = 240` → 마틸다는 **런 종료 10초 전**에 나온다.
- `Enemies.jsx:1465` `hp: sameTypeZombieHpForStage(matildaHpFromWeapons(store.weapons), cache.id)` →
  HP가 **스폰 시점 플레이어 DPS × 1800초**에서 파생된다. 즉 10초 안에 깎을 수 있는 비율은
  구조적으로 항상 **1/180 (0.56%)** 로 고정이다. 전에도 후에도 못 죽인다.
- `matildaSpec.test.js` S1: 접촉은 무적프레임·최대체력과 무관하게 즉사. 클리어 조건은
  `ESCAPE_PORTAL_OPEN_SEC = 210`에 열린 포탈로 탈출하는 것이지 마틸다 격파가 아니다.
- 스테이지 배율도 함께 곱해진다(`STAGE_HP_MULTIPLIER` 1.0/1.2/1.44/1.728) → 스4 마틸다 HP는 약 33만.
  이 역시 죽일 수 있는 값이 아니다.

**마틸다 HP는 난이도 노브가 아니라 "절대 못 죽인다"를 유지하는 자기보정 상수다. +44%는 표시값 변화이고 플레이 영향 0이다.**
따라서 이 항목은 "플레이어가 세진 만큼 스테이지가 쉬워졌는가" 하나만 보면 된다.

## 8. 추가 발견

### A. `pickThree`의 셔플이 균등하지 않다 — 선언 순서가 카드 출현률을 최대 2.9배 왜곡한다 (선재 결함, **CONCERN**)

`HUD.jsx:362`

```js
const shuffled = [...limited].sort(() => Math.random() - 0.5)
return shuffled.slice(0, 3)
```

`sort` 비교자를 난수로 만드는 건 균등 셔플이 아니다. 후보 22개(현실적 그룹 수) 기준 20만 회 실측(측정 D),
"3장 안에 뽑힐 확률"의 공정값은 13.64%인데:

| 위치 | 실측 확률 | 공정 대비 |
|---|---|---|
| idx 0 | 26.41% | **x1.94** |
| idx 3 | 19.77% | x1.45 |
| idx 7 | 17.30% | x1.27 |
| idx16 | 9.24% | **x0.68** |
| idx17 | 9.83% | x0.72 |

**최대 2.86배 격차.** `UPGRADES` 배열 앞쪽(커터칼·연필 계열)이 상시 과다 노출되고, 뒤쪽(상어미사일·이동속도·최대체력)이
과소 노출된다. 이동속도·최대체력은 배열 **맨 끝 2개**라 가장 심하게 손해 본다.

- **이 커밋이 만든 결함은 아니다.** 새 `*Power` 카드는 전부 같은 무기 그룹 안에 삽입돼 **그룹의 상대 순서를 바꾸지 않으므로**,
  이 편향의 크기는 전/후 동일하다. 내 몬테카를로도 이 편향을 그대로 재현해 측정했으므로 A/B 결론은 유효하다.
- **고치지 않았다.** 1줄 수정이지만 전 무기 출현률이 동시에 바뀌어 **사용자가 진행 중인 좀비 HP 보정과 이번 커밋 검증을 동시에 오염**시킨다.
  balanceqa 판단으로 별건 분리가 옳다.
- 수정안 (Fisher–Yates):
  ```js
  const shuffled = [...limited]
  for (let i = shuffled.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1))
    ;[shuffled[i], shuffled[j]] = [shuffled[j], shuffled[i]]
  }
  return shuffled.slice(0, 3)
  ```
  적용 시 **반드시 balanceqa 재측정을 동반**할 것 — 이동속도·최대체력 출현률이 약 1.4배 오르면서
  플레이어 생존력이 함께 오른다.
