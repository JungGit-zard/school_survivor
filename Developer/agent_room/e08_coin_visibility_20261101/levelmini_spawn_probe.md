# E08 코인 몬스터 미노출 — 스폰·배회·도주 관점 조사 (levelmini)

- 날짜: 2026-11-01 / 트리: `ezs-cf` zombie_only HEAD 5f88e2c0 (읽기 전용, 코드 수정 없음)
- 라우팅 receipt: 5bcfc83f / 3a20befe (levelmini). 렌더링 관점은 threemini 별도.
- 거리 표기: units (블록 병기, 1블록 = 4 units, Bang_Rules).

## 결론 요약

E08이 "안 보이는" 주원인은 **세로(portrait) 모바일에서 스폰 링이 가로 시야보다 넓고, E08은 다가오지 않고 스폰 지점(home)에 묶여 있기 때문**이다.
일반 좀비도 같은 링에서 나오지만 플레이어를 쫓아와서 곧 화면에 들어온다. E08만 home 주변 1.2u를 맴돌고, 플레이어가 4.5u 안으로 오면 6.25u까지 달아난다. 그래서 화면 밖에서 태어나면 끝까지 화면 밖에 있을 수 있다.

## 측정값 (scratchpad 계산, `getGameplayGroundReach(fov 30)` 실함수 사용)

| 뷰포트 | 가로 시야 반폭 (가까운쪽 / 먼쪽) | 스폰 링 4.0~6.5u 중 화면 안 비율 | 도주 유지 거리 4.5~6.25u 중 화면 안 비율 |
|---|---|---|---|
| 390x844 portrait | 2.43u(0.61블록) / 4.21u(1.05블록) | **40.9%** | 39.4% |
| 360x740 portrait | 2.56u / 4.43u | **43.4%** | 41.4% |
| 16:9 landscape | 9.35u / 16.2u | 100% | 100% |

- 위아래 시야(위쪽 12.44u, 아래쪽 7.19u)는 충분하다. 막히는 건 **가로**뿐이다.
- 카메라가 플레이어 중앙에 있다는 가정이다. 맵 가장자리에서 카메라가 클램프되면 한쪽은 더 좁아진다.
- 결론: 세로 모바일에서는 **E08 스폰의 약 57~59%가 화면 밖 좌우**에 놓인다.

## 원인 후보

### 1. [확신도 높음] 세로 모바일 가로 시야 < 스폰 링 + E08이 home에 묶여 있음
- 근거:
  - `src/components/Enemies.jsx:152-157` — 스폰 링 `SPAWN_MIN_RADIUS 4.0` / `SPAWN_MAX_RADIUS 6.5` (1.0~1.6블록). 주석은 "가까운쪽 +z reach ≈ 7.2가 가장 빡빡"이라고 적혀 있지만, 이건 가로가 넓은 화면 기준이다. portrait 가로 반폭 2.4~4.4u를 고려하지 않았다.
  - `src/components/Enemies.jsx:274-281` — 각도를 균등하게 뽑는다. 좌우 방향 차단이 없다.
  - `src/components/Enemies.jsx:1855-1861` — E08 버스트도 `spawnPosForBurstType → randomSpawnPos` 같은 링을 쓴다.
  - `src/lib/enemyEntityPool.js:307` — home = 스폰 좌표로 고정된다.
  - `src/lib/enemySimulation.js:37-39,413-435` — LURE 상태에서는 home 반경 1.2u 배회, 1.85u를 넘으면 home으로 돌아간다. **플레이어 쪽으로는 절대 오지 않는다.**
  - `src/lib/gameCameraFraming.js:6-18`, `src/components/Game.jsx:139-174` — 가로 시야 = `tan(15°)·aspect·거리`. 390x844 기준 2.4~4.2u.
- 재현 조건: 390x844 같은 세로 모바일에서 S1~S5 아무 스테이지나 90초/180초를 넘긴다. 좌우로 스폰되면 E08은 화면 밖 home에 머문다. 플레이어가 계속 움직이면 home은 그대로 뒤에 남는다(플레이어 3u/s, 3초면 9u = 2.25블록 멀어짐). 데스크톱 가로 화면에서는 재현되지 않는다.
- 최소 수정안 1줄: E08만 스폰 좌표를 현재 `screenBounds` 안쪽(가장자리 inset 0.6u 이상)에서 뽑는다. 예: `spawnPosOnValidRing` 후보 중 화면 안 후보만 채택하고, 없으면 플레이어 위/아래(±z) 3.0~4.0u로 폴백한다. 부가로 home을 "화면 안 지점"으로 갱신하는 방안도 있지만 1차는 스폰만 고친다.
- 검증 테스트 1줄: `Enemies.test.jsx`에 aspect 390/844 `screenBounds`를 세팅하고 E08 버스트 스폰을 seed 200회 돌려, **100% 스폰 좌표가 screenBounds 안**이고 4.5u(감지 반경) 밖에서 시작하는지 단언한다.

### 2. [확신도 중] 감지 4.5u / 해제 6.25u 도주 밴드 전체가 portrait 가로 시야 밖
- 근거: `src/lib/enemySimulation.js:35-36,389-411` — 4.5u 안에 들어오면 FLEE, 6.25u 이상 벌어지면 LURE로 돌아간다. 도주 중 E08은 플레이어로부터 4.5~6.25u(1.1~1.6블록)를 유지하려 한다. portrait 가로 반폭은 2.4~4.4u다. 그래서 **좌우로 쫓으면 보이기 전에 도망가기 시작하고, 계속 화면 경계 밖에 머문다**(위 표, 도주 밴드 화면 안 비율 39~41%). 지그재그 wobble 0.62 때문에 가끔 들어왔다 나간다. 이게 "보였다 안 보였다"로 체감된다. 도주 속도 0.88×1.35 = 1.19u/s, 플레이어 3u/s. 따라잡을 수는 있지만 플레이어가 위치를 모르면 쫓지 않는다.
- 참고: 기존 테스트 `src/lib/enemySimulation.test.js:467-474`는 E08을 x=6(정확히 가로)에 놓고 "배회 유지"를 검증한다. portrait에서는 화면 밖 좌표다. HUD 치트 소환(`src/components/HUD.jsx:134-148`)은 조이스틱 방향 **2.2u 앞**(감지 반경 안)에 놓는다. 그래서 QA/시각 검수에서는 항상 바로 보이고 도주한다. **검수 경로가 실 스폰 경로를 가린다.**
- 재현 조건: portrait에서 E08을 발견해 좌우로 쫓아간다. E08이 화면 좌우 끝에서 들락날락한다.
- 최소 수정안 1줄: `E08_COIN_DETECT_DISTANCE`를 4.5에서 2.6u(0.65블록)로, `E08_COIN_LOSE_DISTANCE`를 6.25에서 3.6u(0.9블록)로 줄인다. portrait 가로 반폭(근 2.43u ~ 원 4.21u) 안에서 도주가 시작되고 끝나게 한다. 랜드스케이프 체감 변화는 balanceqa가 확인한다.
- 검증 테스트 1줄: `enemySimulation.test.js`에서 플레이어를 x축으로 1.19u/s보다 빠르게 접근시켜 600프레임 동안 `|dx| ≤ 4.21`(390x844 원쪽 반폭)인 프레임 비율이 80% 이상인지 단언한다.

### 3. [확신도 낮음~중] 발화 플래그 선기록 + 동시 천장 150 → 무음 소실 (재시도 없음)
- 근거:

  - `src/components/Enemies.jsx:1641` — `addEnemies`는 `150 - (풀 + 특수 + 대기열) <= 0`이면 break한다.
  - `src/lib/pooledEnemySpawnDrain.js:19-24` — 큐(256)가 가득 차면 drop된다.

  - 어느 경우든 E08 이벤트는 다시 시도되지 않는다. E08 이벤트는 `getRuntimeSpawnEventsForStage`(`src/lib/burstEvents.js:335-337`)에서 배열 **맨 끝**에 붙는다. 같은 초의 스테이지 버스트가 먼저 천장을 채우면 E08이 잘린다.
- 위험 구간: 180초. 보스 구간(B01/B02 150초 등장 이후)이고 184초 러시 직전이라 S2~S4는 필드 밀도가 높다. S1(스테이지 총 약 100마리)의 90초에는 가능성이 낮다.

- 재현 조건: S2~S4에서 180초에 활성 적 150 근처(소크 `saturateRuns`).
- 최소 수정안 1줄: E08(`rewardEvent: 'coinMonster'`) 이벤트는 실제 spawn 성공 시에만 fired=1로 남기고, 실패하면 0으로 되돌린다(확장 스테이지 보스 경로 `Enemies.jsx:1787,1827`과 같은 패턴). 또는 천장 판정에서 E08을 1칸 예약석으로 제외한다.
- 검증 테스트 1줄: `gameplaySoak`(saturateRuns) 또는 `Enemies.test.jsx`에서 활성 150 상태로 90초/180초를 통과시킨 뒤, 칸이 빈 다음 프레임에 E08이 정확히 1마리 활성인지 단언한다.

## 배제/확인한 항목 (원인 아님)

- 맵 경계 밖 스폰/즉시 제거: 아니다. 링 후보는 `isInsideSpawnBounds`로 거른다(`Enemies.jsx:289`). E08은 screen runner가 아니라 경계 밖 despawn(`enemySimulation.js:1005`) 대상이 아니다. 도주 중 벽 margin 1.1u에서 바깥 성분을 -0.65로 반사한다(`enemySimulation.js:402-405`). 경계에서 막히고 사라지지 않는다.
- 수명/디스폰 타이머: E08 전용 수명이나 디스폰 경로가 없다. 처치 전까지 계속 남는다.
- 캐치업 스폰 시계(`Enemies.jsx:1990`): 시각을 앞당길 뿐 이벤트를 건너뛰지 않는다.
- 맵 크기: S1 10×14.4, S2/S3/S5 7.5×19.2, S4 9.36×16(half). 스폰 링 6.5u와 home 배회 1.85u는 모두 맵 안에 들어간다.
- stale 주석: `src/lib/enemyEntityPool.js:26` "아직 스폰 스케줄에는 넣지 않고 치트 소환 전용"은 현재 사실과 다르다(90/180초 스케줄 편입됨). 수정 대상은 아니고 기록만 한다.

## Balance_QA_Mini(balanceqa) 핸드오프 / Acceptance Criteria
1. 390x844, 360x740 portrait에서 S1~S5 각 90초/180초 E08 스폰 좌표가 200회 시드 중 100% `screenBounds` 안이다.
