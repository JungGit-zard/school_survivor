# 1차 그래픽·전투 가독성 비평

- 일자: 2026-07-30
- 역할: 그래픽/전투 가독성 1차 비평 (평가 전용)
- 범위: 현재 작업 트리의 Three.js/R3F 소스와 지정 런타임 증거를 읽고 채점만 했다. 게임 코드, Firebase, Graphics Studio 값, 브라우저 저장소는 변경하거나 접근하지 않았다.
- 라우팅: Escape! zombie school 필수 라우팅 표에서 이 평가는 `threemini` 범주(Three.js·툰 3D·VFX)이며, 본 `Graphic_designer/` 산출물을 그래픽 검토 증적으로 남긴다. UI/밸런스/오디오/성능은 해당 범주 점수만 제한적으로 교차 평가했다.

## 증거의 범위와 한계

유일한 **현재 런타임 시각 증거**는 [완료 로딩 타이틀 캡처](../Quaility_Assurance/evidence/critic_round1_title_loaded_2026-07-30.png)다. 이 캡처에서는 중앙 툰 3D 군상, 주황/백색 타이틀, Google 패널, `게임 시작` CTA를 확인했다. 초기 로딩 프레임인 `Quaility_Assurance/evidence/critic_round1_title_2026-07-30.png`는 지시대로 완성 화면 평가에 사용하지 않았다.

현재 전투, 피격, 사망, 레벨업, 보스, 모바일 조작, 실제 기기 성능, 실제 음향을 담은 동시대 런타임 증거는 제공되지 않았다. 따라서 해당 구현이 소스에 존재해도 **체감 통과 증거로 취급하지 않았고**, 직접 증거가 없는 항목에는 8점 이상을 주지 않았다. 작업 트리에는 평가 범위 밖의 기존 변경/미추적 파일도 있으므로, 이 문서는 현 작업 트리 읽기 결과이지 특정 커밋 또는 AAB의 인증이 아니다.

확인한 주요 근거는 다음과 같다.

- 툰 재질과 실루엣 외곽선의 stencil 방식: `Developer/r3f_prototype/src/lib/toon.js:31-43, 59-63`.
- 타이틀의 cyan/magenta 광원과 Studio 연동 캐릭터 구성: `Developer/r3f_prototype/src/components/TitleScene3D.jsx:18-35`.
- 타이틀 문구/CTA의 safe-area, 타이포 크기, 최소 버튼 높이: `Developer/r3f_prototype/src/components/TitleScreen.jsx:369, 573-648, 668-687`.
- 풀 적의 3D 실루엣·외곽선 보존과 체력바: `Developer/r3f_prototype/src/components/PooledEnemyVisuals.js:2-16, 46-47, 91`; `Developer/r3f_prototype/src/components/ZombieInstanceLayer.jsx:72-84, 151-152`.
- 적 피격의 spark·피해 숫자·크리티컬 shake·사망 SFX 배선: `Developer/r3f_prototype/src/components/Enemies.jsx:826-931`; `Developer/r3f_prototype/src/lib/enemyHitVfx.js:3-6`; `Developer/r3f_prototype/src/lib/damageNumbers.js:9-18, 82-85`.
- 접근성/조작 관련 코드: `Developer/r3f_prototype/src/components/VirtualJoystick.jsx:8, 69-74`; `Developer/r3f_prototype/src/components/HUD.jsx:743-745, 762, 860-877, 1204-1208, 1481-1490`.
- 적/투사체 풀의 상한: `Developer/r3f_prototype/src/lib/enemyEntityPool.js:2, 62-103`; `Developer/r3f_prototype/src/lib/enemyProjectilePool.js:2, 15-24`.
- 기존 QA의 한계: `Quaility_Assurance/current_risk_register.md`는 모바일 조이스틱·pause/resume을 `testing`, ReadPixels/번들 크기를 `open`으로 기록한다. `Quaility_Assurance/internal_gameplay_500_run_stress_2026-07-02.md`는 상태 시뮬레이션이며 실시간 렌더·애니메이션·오디오·터치 검증이 아니라고 명시한다.

## 7개 범주 채점

가중치는 이번 비평의 주 렌즈인 시각/전투 가독성에 맞춰 정했다. 총점은 각 점수 × 가중치의 합이다.

| 범주 | 점수 | 가중치 | 근거와 감점 |
| --- | ---: | ---: | --- |
| 1. visual readability / art direction | 6.5 | 28% | 완료 타이틀은 검은 외곽선, 푸른/자주 조명, 주황·백색 제목, 분명한 CTA로 즉시 장르를 전달한다. 그러나 텍스트가 중앙 군상과 겹치고, 플레이어·좀비·Doge·소품이 한 덩어리여서 첫 시선의 우선순위가 흐려진다. 실제 전투 실루엣 증거가 없어 8점 불가. |
| 2. core combat loop / game feel | 4.5 | 20% | spark·피해 숫자·넉백·크리티컬 shake·사망 연출의 코드 경로는 있다. 다만 전투 프레임이 한 장도 없어, 적 20~85마리 속에서 공격 방향·피격 대상·회피 공간이 읽히는지 확인하지 못했다. |
| 3. progression / balance | 5.5 | 13% | 240초 스테이지, 보스/포탈/마틸다 시간표(`stageConfig.js:6, 17-29`)와 무기 등장 레벨·Lv.5 상한(`weaponCatalog.js:17-78`, `upgrades.js:131-171`)은 존재한다. 하지만 이번 빌드의 실제 레벨업 선택/후반 압박/실패 원인을 보여주는 플레이 증거가 없다. |
| 4. UI / mobile / accessibility | 5.5 | 14% | 제목·CTA의 safe-area와 58px CTA, HUD 대화의 ARIA live, 3열 카드 구조는 긍정적이다. 반면 현재 리스크 레지스터에서 조이스틱과 pause/resume은 아직 `testing`이고, 390px 이하 실제 전투 화면 증거가 없다. |
| 5. audio / feedback | 4.0 | 8% | SFX 레지스트리와 타격/사망 호출은 확인했지만(`sfxRegistry.js:13-102`, `Enemies.jsx:825-931`), 재생 성공·다발 전투에서의 혼잡·볼륨 균형을 들을 수 있는 증거가 없다. |
| 6. performance / stability | 5.0 | 10% | 200 적/32 투사체 typed-array 풀과 InstancedMesh는 좋은 방향이다. 그러나 현재 QA가 ReadPixels 경고와 500kB 초과 번들을 `open`으로 남기며, 실제 저사양 모바일 FPS/메모리 증거가 없다. |
| 7. product / onboarding / retention | 5.5 | 7% | 타이틀의 단일 `게임 시작` CTA와 “4분만 버티면” 목표는 간결하다. 하지만 자동 공격·XP 수집·3장 업그레이드라는 첫 판의 핵심 약속이 로딩 타이틀에서 보이지 않고, 첫 판/결과/재도전의 런타임 증거도 없다. |

**전체 점수: 5.4 / 10**  
계산: `6.5×0.28 + 4.5×0.20 + 5.5×0.13 + 5.5×0.14 + 4.0×0.08 + 5.0×0.10 + 5.5×0.07 = 5.41` → 소수 첫째 자리 반올림. 이 점수는 “타이틀의 미술 방향은 확인됐지만, 전투 가독성은 아직 증명되지 않았다”는 뜻이며 구현 부재 판정은 아니다.

## 8점 재평가의 최소 공통 게이트

다음 네 묶음이 모두 같은 후보 빌드에서 충족될 때만 이 비평을 8점대 재평가 대상으로 올린다.

1. 현재 완료 타이틀과 Stage 1의 초반/밀집/보스(또는 마틸다) 전투를 390×844 및 1280×720으로 제시한다.
2. 각 전투 상태에서 플레이어, 적 실루엣, 피격·사망 VFX, HUD/조이스틱이 동시에 판독 가능함을 그래픽과 QA가 확인한다.
3. 실제 기기 또는 동등 환경에서 오디오 재생, reduced-motion/reduced-effects, pause/resume, 레벨업 카드 조작을 검수한다.
4. 저사양 모바일과 데스크톱의 성능 기록을 남기고, 현재 열린 ReadPixels/번들 위험의 상태를 `open` 그대로 방치하지 않고 판정한다.

이 게이트 전에는 소스의 존재만으로 8점 이상을 부여하지 않는다.

## 자체 점검

- 산출물 경로: `Graphic_designer/critic_round1_graphics_2026-07-30.md`
