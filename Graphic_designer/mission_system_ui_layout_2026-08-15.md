## 1. 핵심 방향

미션 UI는 타이틀 이후 로비/홈 흐름에서 시작한다. 타이틀 화면은 잠금 대상이므로 미션 진입점, 문구, 배지, 설정, 그래픽을 타이틀에 추가하지 않는다.

가장 작은 MVP는 다음 4개 화면 조각만으로 충분하다.

1. 로비 하단 내비게이션의 미션 버튼
2. 로비 위에 뜨는 미션 센터 모달/스크린
3. 게임 중 좌측 상단 컨트롤 근처의 접이식 고정 미션 추적기
4. 결과 화면의 미션 진행/완료 요약 섹션

장식 애니메이션, 캐릭터 연출, 복잡한 시즌 패스형 보상 트랙, 별도 3D 미션 오브젝트 연출은 MVP 이후로 미룬다. 우선순위는 “읽기 쉬움, 터치 가능, 전투 시야 방해 최소화, 기존 HUD와 충돌 없음”이다.

## 2. 현재 UI 구조에서의 배치 판단

### 2.1 로비

현재 로비는 다음 구조다.

- 상단 sticky 상태바: 프로필, 골드, 설정, 시즌 스트립
- 중앙: 스테이지 카드 리스트 스크롤
- 하단: bottom nav. 현재 `gridTemplateColumns: repeat(4, minmax(0, 1fr))`인데 버튼은 무기/랭킹/상점 3개가 렌더링된다.

따라서 미션 버튼은 하단 nav의 빈 4번째 슬롯에 넣는 것이 가장 작고 안전하다.

권장 순서:

1. 무기
2. 미션
3. 랭킹
4. 상점

이유:

- 타이틀을 건드리지 않는다.
- 스테이지 카드 위에 새 CTA를 얹지 않아 보스 프리뷰, 입장 버튼, 랭킹 버튼과 충돌하지 않는다.
- 이미 4열 CSS가 준비되어 있어 레이아웃 변경량이 작다.
- 하단 버튼은 기존 최소 높이 48px라 모바일 터치 타깃 기준을 만족한다.

### 2.2 게임 HUD

현재 HUD 주요 배치:

- XP bar: 최상단 전체 폭 9px
- 좌측 상단: pause 44x44, quest bag 44x44, dev buttons
- 중앙 상단: stage chip + timer
- 우측 상단: gold chip
- 중앙/상단: 보스, 투사체, 마틸다, 대형 스폰 경고
- 중앙: 레벨업/대화/퀘스트 팝업
- 하단 중앙: 무기 아이콘, HP bar
- bottom 102px: 포탈 목표 안내

미션 추적기는 전투 중 항상 큰 패널로 보이면 안 된다. 추천 위치는 좌측 상단 컨트롤 아래쪽이며, 기본은 1줄 접힘 상태다.

- 기본 상태: `미션 1/3` + 가장 가까운 진행 1개만 표시
- 펼침 상태: 최대 2개까지 표시
- 경고/대화/레벨업/결과/퀘스트 인벤토리/일시정지 중에는 자동 숨김 또는 해당 오버레이 아래 우선순위로 밀림

### 2.3 결과 화면

현재 gameover/cleared 결과 모달은 폭이 작다. 미션 요약을 너무 많이 넣으면 버튼 영역과 겹친다.

권장:

- 결과 모달 내부 골드 획득 문장 아래에 1~2줄 요약만 추가
- “완료 2개 · 보상 대기 1개” 같은 숫자 요약
- 완료한 미션 1개만 대표 카드로 보여주고, 나머지는 “미션 센터에서 확인”으로 유도
- 보상 수령은 결과 화면에서 전부 처리하지 않고, MVP에서는 미션 센터로 유도

## 3. 모바일 로비 와이어프레임

```text
┌────────────────────────────┐
│ 플레이어명             🪙  │  sticky status bar
│ [시즌] 여름방학 D-3        │
├────────────────────────────┤
│ ┌────────────────────────┐ │
│ │ Stage 1 보스 프리뷰     │ │
│ │ 최고기록 02:10          │ │
│ │              [입장하기] │ │
│ │ [기록]                  │ │
│ └────────────────────────┘ │
│ ┌────────────────────────┐ │
│ │ Stage 2 ...             │ │
│ └────────────────────────┘ │
│                            │
├────────────────────────────┤
│ [무기] [미션●2] [랭킹] [상점] │  bottom nav, each min 48px
└────────────────────────────┘
```

로비 미션 버튼 규칙:

- 버튼 라벨: `미션`
- 보상 수령 가능 수가 있으면 배지: `●2` 또는 `2`
- 활성 진행 미션이 있으나 수령 가능이 없으면 작은 진행 점만 표시
- 새 미션이 잠금 해제되면 `NEW`는 최대 1회성으로만 표시
- 버튼 터치 영역: 최소 48x48px 유지
- 접근성 이름 예시: `미션 센터 열기, 받을 보상 2개`

## 4. 미션 센터 목록 와이어프레임

모바일은 전체 화면에 가까운 모달이 가장 안전하다. 로비 위에 뜨지만 별도 screen처럼 행동한다.

```text
┌────────────────────────────┐
│ 미션 센터              [×] │  header 56px
│ 오늘의 목표와 진행 보상     │
├────────────────────────────┤
│ [추천] [진행중] [완료] [전체]│  horizontal tabs, 44px target
├────────────────────────────┤
│ 받을 보상 2개        [모두받기]│ optional claim strip
├────────────────────────────┤
│ ┌────────────────────────┐ │
│ │ ★ 첫 Stage 1 탈출       │ │
│ │ Stage 1 클리어 1회      │ │
│ │ ███████░░░ 0/1          │ │
│ │ 보상 20골드       [받기] │ │
│ └────────────────────────┘ │
│ ┌────────────────────────┐ │
│ │ 핀  첫 30초 버티기      │ │
│ │ Stage 1 30초 생존       │ │
│ │ █████░░░░░ 21/30초      │ │
│ │ 보상 5골드       [고정] │ │
│ └────────────────────────┘ │
│ ┌────────────────────────┐ │
│ │ 🔒 Stage 2 탈출         │ │
│ │ Stage 2 진입 후 공개    │ │
│ └────────────────────────┘ │
└────────────────────────────┘
```

권장 치수:

- 모달 폭: `min(100vw - 24px, 560px)`
- 모바일 높이: `calc(100dvh - safe-area - 24px)`
- 헤더 높이: 56~64px
- 탭 버튼 높이: 최소 44px
- 카드 최소 높이: 96px
- 카드 내부 주요 CTA: 최소 44px 높이
- 좌우 패딩: 12px, 카드 내부 10~12px
- 카드 간격: 9~12px

목록 탭/필터:

- MVP 탭: `추천`, `진행중`, `완료`, `전체`
- `추천`: 30종 중 현재 진행 단계에서 보여줄 3~5개. 첫 구현은 기존 카운터 기반 쉬운 10개 위주.
- `진행중`: active 또는 progress > 0
- `완료`: completed + claimable/claimed
- `전체`: 잠금 포함 전체 목록

정렬:

1. 받을 수 있음
2. 핀 고정
3. 거의 완료됨
4. 추천 티어 낮은 순
5. 잠금

## 5. 미션 카드 해부

```text
┌────────────────────────────┐
│ [상태] 미션명          [핀] │
│ 한 줄 목표 설명             │
│ ███████░░░ 7/10             │
│ 보상 🪙10        [받기/보기] │
└────────────────────────────┘
```

구성 요소:

- 상태 칩:
  - 진행중: `진행`
  - 완료/수령 가능: `완료`
  - 수령 완료: `받음`
  - 잠금: `잠김`
- 제목: 1줄 기본, 한국어 12~14자 이상은 2줄 허용
- 목표 설명: 1~2줄, `word-break: keep-all`, `overflow-wrap: anywhere`
- 진행률: 숫자와 bar를 동시에 제공
- 보상: 골드 아이콘/텍스트
- CTA:
  - 수령 가능: `받기`
  - 진행중: `보기`
  - 수령 완료: disabled `받음`
  - 잠금: disabled `잠김`
- 핀 버튼: 44x44 독립 터치 영역. 텍스트보다 아이콘 + 접근성 라벨 권장.

상태별 시각 규칙:

- 진행중: paper 배경 + ink 텍스트 + cta 보조 강조
- 완료/수령 가능: reward 배경 또는 reward 테두리, CTA는 reward intent
- 수령 완료: 채도 낮춤, 체크 표시, CTA 비활성
- 잠금: opacity만 과하게 낮추지 말고 텍스트 대비 유지. 잠금 이유 1줄 제공
- 오류/오프라인: 카드 상단에 작은 경고 칩, 진행 데이터는 마지막 저장값 표시

## 6. 미션 상세 와이어프레임

상세는 목록 카드 탭/클릭으로 열리는 하단 시트 또는 동일 모달 내부 detail view가 적합하다. MVP는 동일 모달 내부 전환이 구현 단순성이 높다.

```text
┌────────────────────────────┐
│ [←] 첫 Stage 1 탈출        │
├────────────────────────────┤
│ 목표                         │
│ Stage 1에서 240초까지 생존하고│
│ 탈출 포탈을 통해 클리어한다.  │
│                              │
│ 진행                         │
│ ███████░░░ 0/1               │
│                              │
│ 보상                         │
│ 🪙 20 골드                   │
│                              │
│ 도움말                       │
│ 먼저 Stage 1에서 1분 생존을  │
│ 목표로 움직여 보세요.        │
├────────────────────────────┤
│ [고정하기]             [닫기] │
│ 완료 시:              [받기] │
└────────────────────────────┘
```

상세 화면 규칙:

- 뒤로가기 버튼: 44x44
- 닫기 버튼: 44x44
- 목표 설명은 기획 문서의 완료 조건을 그대로 사용자 친화 문장으로 변환
- 내부 개발용 트래킹 노트는 유저에게 노출하지 않는다
- 보상 수치는 Balance_QA 확정 전에는 “제안” 수치를 그대로 상품처럼 과장 노출하지 않는다. 실제 구현 전 Balance_QA 확정 필요.

## 7. 고정 미션 / 게임 HUD 추적기

인게임 추적기는 플레이 방해 최소화가 최우선이다.

```text
기본 접힘
┌──────────────┐
│ 미션 1/3  ▾  │
│ 7/10 녹색좀비 │
└──────────────┘

펼침
┌──────────────────┐
│ 고정 미션      ▴ │
│ 녹색좀비 7/10    │
│ 첫 30초 21/30초  │
└──────────────────┘
```

권장 위치:

- 좌측 상단 pause/quest bag 아래
- 대략 `top: safe-top + 52~60px`, `left: 14px`
- 폭: 모바일 `min(220px, calc(100vw - 28px))`
- 전투 중 기본 높이: 48~64px
- 펼침 높이: 최대 116px

표시 우선순위:

1. 보스/마틸다/투사체/대형 스폰 경고가 뜨면 미션 tracker는 접힘 또는 숨김
2. 레벨업, 일시정지, 퀘스트 인벤토리, 대화, 결과 화면에서는 숨김
3. 포탈 목표 안내와 겹치지 않도록 하단 배치는 피함
4. 좌측 상단 dev button이 켜진 개발 모드에서는 tracker가 버튼 아래로 내려가거나 숨김

터치/조작:

- 탭: 접기/펼치기
- 길게 누르기: MVP에서는 사용하지 않음
- 핀 변경은 미션 센터에서만 허용. 전투 중 핀 편집은 MVP 제외

접근성:

- `role="status"` 또는 aria-live polite는 완료 순간 toast에만 사용
- 평상시 진행 수치가 매 프레임 바뀌는 미션은 aria-live로 계속 읽히지 않게 한다

## 8. 결과 화면 미션 요약 와이어프레임

│ 획득 골드 20 / 총 120 │

MVP 권장:

- 완료 미션 최대 1개 대표 표시
- claimable count 표시
- 버튼은 새로 추가하지 않고, 가능하면 기존 결과 CTA 중 로비/상점 흐름 이후 미션 센터 배지를 통해 받게 한다
- 결과 모달에 버튼을 추가해야 한다면 44px 이상, 기존 4개 버튼을 더 작게 만들지 않는다

## 9. 데스크톱 레이아웃

현재 `ReadyGameApp`의 phoneFrame은 100vw/100vh 전체 화면이다. 데스크톱에서도 모바일 UI가 늘어나 보일 수 있으므로 mission center는 최대 폭을 제한한다.

```text
┌──────────────────────────────────────────────┐
│ Lobby / Gameplay background                   │
│                                              │
│      ┌────────────────────────────────┐      │
│      │ 미션 센터                  [×] │      │
│      ├──────────────┬─────────────────┤      │
│      │ 추천/진행/완료 │ 상세 또는 목록     │      │
│      │ 미션 카드 목록 │ 선택 미션 상세     │      │
│      │              │                 │      │
│      └──────────────┴─────────────────┘      │
└──────────────────────────────────────────────┘
```

데스크톱 규칙:

- 폭 720px 이상에서는 2열 가능
  - 좌측: 목록 320px
  - 우측: 상세 360px 이상
- 폭 720px 미만에서는 모바일 단일 열 유지
- 모달 최대 폭: 760px
- 모달 최대 높이: `min(82dvh, 720px)`
- 마우스 hover는 보조 효과만. 핵심 상태는 텍스트/아이콘/색으로 항상 보인다.

### 10.2 오류 상태

- 제목: `미션 정보를 불러오지 못했습니다`
- 본문: `잠시 후 다시 시도해 주세요. 게임 진행은 계속할 수 있어요.`
- CTA: `다시 시도`, `닫기`
- 원문 에러 stack은 유저 화면에 기본 노출하지 않는다. 개발 모드에서만 상세 확인.

### 10.3 오프라인/저장 대기

- 상단 strip: `오프라인 진행 중 · 연결되면 저장됩니다`
- 수령 버튼은 서버/클라우드 지급 확정이 필요한 경우 비활성 또는 `저장 대기` 상태
- 로컬 진행률은 마지막 확인값과 이번 런 변화값을 분리해서 표시하는 것이 안전하다

## 11. 키보드 / 마우스 / 터치 행동

- 모든 버튼 최소 터치 높이: 44px 이상, 주요 CTA는 48px 권장
- `Esc`: 미션 상세 → 목록, 목록 모달 → 닫기
- `Tab`: 닫기, 탭, 카드, CTA 순서로 자연스럽게 이동
- `Enter/Space`: 선택/수령
- 배경 클릭 닫기: 모바일 실수 방지를 위해 MVP에서는 비추천. 닫기 버튼을 명확히 둔다
- 포커스 표시: 기존 HUD처럼 `outline: 3px solid #fff8e8; outline-offset: 3px` 계열 사용
- disabled 버튼은 회색만 쓰지 말고 `받음`, `잠김`, `저장 대기` 텍스트를 같이 표시

## 12. 접근성 / 한국어 텍스트 맞춤

한국어 미션명은 길어질 수 있으므로 한 줄 고정을 피한다.

권장:

- 미션명: 15~17px, 1~2줄 허용
- 목표 설명: 12~14px, 1~2줄
- 진행 숫자: `7/10`, `21/30초`처럼 단위 포함
- `word-break: keep-all` + `overflow-wrap: anywhere`
- 색상만으로 상태 구분 금지. 상태 칩 텍스트 필수
- 진행 bar는 숫자와 같이 제공
- 완료 toast는 `aria-live="polite"`, 보상 수령 성공은 `role="status"`
- 반복 진행 갱신은 스크린리더에 과도하게 읽히지 않게 한다

## 15. 변경 금지/주의

- 타이틀 화면에는 미션 진입점을 추가하지 않는다.
- 사운드/SFX/BGM은 이번 기획 범위 밖이며, 추후 효과음이 필요하면 `soundmini` 관여가 필요하다.
- 기존 HUD의 보스/마틸다/투사체/대형 스폰 경고보다 미션 tracker가 높은 우선순위를 갖지 않는다.
- 전투 중 시야를 가리는 중앙 대형 미션 팝업은 완료 순간에도 피한다. 완료 알림은 작게, 또는 결과 화면에서 요약한다.
- 기존 퀘스트 가방 UI와 미션 UI를 혼동하지 않게 라벨을 분리한다. 퀘스트는 런 내부 NPC/기물, 미션은 계정/진행 목표다.
