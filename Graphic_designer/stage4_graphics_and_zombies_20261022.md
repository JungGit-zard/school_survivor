- [수용 제안] 남쪽 시작점·학생 퀘스트 표적·자판기 접근·가마솥 양측 우회는 서로 다른 경로로 확인한다. 현재 통행 검증 PASS로 표기하지 않는다.
- [수용 제안] 장식물이 공격 경고를 가리면 우선 장식의 위치/강조를 재검토한다. 모든 적을 벽 너머 표시하거나 카메라를 전면 교체하는 해법은 제외한다.

### 3.3 중앙 압력 가마솥과 B04 공격 시각
- [고정] 가마솥은 15s 주기·3s 예고·반경 3.2 units/0.8 blocks 폭발을 유지한다. 시각 개선을 이유로 판정·주기·원점을 바꾸지 않는다[S07].
- [제안] 예고 동안 바닥 반경 경계+압력계 방향 변화+뚜껑 진동을 함께 사용한다. 기존 끓음·흔들림 경로를 재사용하고 새 대형 연기벽은 만들지 않는다.
- [제안] 경계는 판정의 월드 반경에 정렬한다. base scale 0.4·Studio transform 때문에 링을 재차 축소/확대하는 위험을 별도로 점검한다[S06].
- [제안] 발동은 짧은 저층 링/국물 파편으로 읽고 증기는 위로 분산한다. 파편 비행 거리 전체가 피해 거리라는 인상을 주지 않는다.
- [고정] B04는 기존 chef이며 HP 50% 이하 전환·1000ms 페이즈 상수를 유지한다. 새 모자·거대 솥 갑옷·다른 얼굴로 교체하지 않는다[S08-S10].
- [주의] 실제 Stage4 Enemy는 별도 국물 대폭발을 먼저 소비하고 done에서 phase2로 진입한다. ‘50% 뒤 정확히 1000ms만에 돌진’이라고 총연출 시간을 단정하지 않는다[S09].
- [제안] 국물 대폭발의 세 원 후보/1.1 units/0.275 blocks 반경·1200ms 예고·250ms 발동은 기존 별도 공격으로 보존한다[S10].
- [제안] 가마솥 원은 동심 압력 눈금, B04 국물 원은 분절된 그릇 테두리로 구별한다. 동일 노랑/주황 계열이어도 출처를 형상으로 식별한다.
- [제안] B04 포격은 팔/상체 준비→투사체→착탄, 격노는 모자/몸통 포즈→진행 방향으로 읽히게 한다. 피해 flash와 분노 예고를 같은 지속 흰색으로 쓰지 않는다.
- [제안] 격노 전환·가마솥 마지막 예고가 겹치면 신규 적 예고 시작을 유예한다. 기존 보스/가마솥 피해 창 자체를 지연·삭제하지 않는다.
- [수용 제안] 경고의 시작·최대 범위·발동·종료를 프레임 단위로 대조하고 일시정지/사망/런 전환 뒤 잔존 VFX가 없어야 한다. 이번에는 실행하지 않았다.

### 3.4 모바일 판독·가림·비용
- [제안] 모바일 검토 화면은 360×640 및 가로 전환을 포함한다. 이는 검수 조건 제안이며 현재 지원 해상도 실측 주장이 아니다.
- [제안] 적의 머리 장비·손 장비·상체 폭 중 두 가지로 식별하게 하고, 미세 글자·표정 텍스처만으로 역할을 전달하지 않는다.
- [제안] 기본·예고·공격·회복을 무음/회색조에서도 구별한다. 점멸 대신 자세 고정·외곽 형태·방향 지시를 우선한다.
- [제안] 실제 카메라와 모델 중심을 잇는 광선 기준으로 냉장고 뒤·남벽·가마솥 뒤 시야를 확인한다. 월드 +Z 정면만 보고 합격시키지 않는다.
- [제안] 최소 기기에서 기존 baseline 대비 CPU/GPU frame time·draw call·texture memory를 측정한 뒤 예산을 승인한다. 미측정 FPS나 절대 성능 PASS를 쓰지 않는다.
- [제안] 품질 저하는 미세 병/음식·파편 수→장식 음영 순서로 줄이고, 적 실루엣·공격 방향·피해 경계는 마지막까지 유지한다.
- [제안] 신규 실시간 그림자·화면 전체 outline·bloom·굴절·새 전역 조명을 기본 범위에서 제외한다. 기존 가구당 선택 외곽선 제한을 유지한다[S05].

## 4. 신규 좀비 범위와 공통 구현 계약
- [권장 P1] 급식 배식원 1종만 우선 추천한다. 기존 일반 근접 적 계열을 바탕으로 실루엣/짧은 공격 준비를 읽히게 하는 최소 slice다.
- [선택 P2] 식판 운반원·국자 투척수·청소 당번 3종은 독립 선택지다. 셋 동시 투입이나 P1 필수 종속 조건이 아니다.
- [미등록] `C4_SERVE`, `C4_TRAY`, `C4_LADLE`, `C4_MOP`는 문서용 가칭이다. 이미 등록된 enemy ID·DB 키·Studio item ID라고 주장하지 않는다.
- [범위] HP·공격력·속도·경험치·전역 배율은 여기서 새 숫자로 정하지 않는다. 기존 스탯/실효값 확인 후 levelmini·balanceqa가 승인할 후속 항목이다.
- [편성 제안] 신규 개체는 기존 일반 요청 일부를 대체한다. 전역 150 상한·큐·보충·보스 예약을 늘리는 추가 물량 해법은 금지한다[S12,S14].
- [공통 제안] spawn reveal→approach→windup→attack→recovery→approach, 어느 상태에서든 death/cancel→cleanup의 단방향 종료를 가진다.
- [공통 제안] 경고 중 사망·런 종료·일시정지는 타이머/피해/표식을 함께 정리한다. 적 시계와 벽시계를 혼용해 화면 밖 예고를 소모하지 않는다.
- [공통 제안] generation 포함 슬롯 손잡이를 사용하고 재사용 때 방향 잠금·피해 소비·표식 소유자·attack timer를 모두 초기화한다[S12].
- [공통 제안] 신규 일반 적을 Enemy.jsx 개별 React/Rapier body로 우회 증설하지 않는다. 일반 pool·instance 경로에서 가능한 범위를 먼저 검토한다.
- [공통 제안] E01/E04/E05의 전역 외형·공격을 바꾸지 않는다. Stage4 가칭 variant와 전용 등록이 필요하면 기존 숫자 코드 충돌·확장 타입 충돌부터 검토한다.
- [주의] ENEMY_STATS 또는 ZombieMesh 분기만 추가하는 것은 불충분하다. 타입 표·simulation·instance 부품·Studio 연결·스폰·정리까지 한 slice여야 한다[S12-S14].

### 4.2 P2 선택 — 식판 운반원 `C4_TRAY`
- [목적 제안] 느린 몸통 방패가 아니라 식판을 묶어 들고 짧게 직진하는 방향형 적이다. 보스의 긴 돌진보다 짧고 명확한 빈틈을 가진다.
- [실루엣 제안] 한쪽 어깨 위 비대칭 식판 묶음, 낮은 사각 머리, 갈색 앞치마, 넓은 발. 이동 카트 전체를 장착하지 않아 가구와 구별한다.
- [부품 제안] 일반 리그·트레이 묶음·한쪽 어깨 받침·두꺼운 장갑. 기존 rolling tray rack 전체를 적 collider로 복제하지 않는다.
- [크기 제안] 높이 1.35 units/0.3375 blocks, 폭 0.8/0.2, 깊이 0.65/0.1625; 수평 몸통 반경 후보 0.32/0.08.
- [애니메이션 제안] approach의 흔들리는 식판→한 발 뒤로 디딤→windup 동안 식판 수평 고정→짧은 직진→상체 숙여 균형 회복→approach.
- [시간 제안] windup 900ms, attack 최대 600ms, recovery 1200ms. 돌진 도중 방향 재조준·추가 회전은 없다.
- [공격 제안] 이동 길이 상한 2.4 units/0.6 blocks의 짧은 직선; 기존 charge 충돌·정지 소비 경로를 재사용 가능한지 먼저 확인한다.
- [대응 제안] 옆으로 회피하거나 solid 뒤로 유도한다. 충돌 즉시 회복, 벽을 밀며 접촉 피해를 연속 적립하지 않는다.
- [편성 제안] 90~140초 후보에서 기존 charger 요청 하나를 대체, 동시 최대 1체 후보; P1과 더해 개체 수를 증가시키지 않는다.
- [호환 제안] B04 phase2 중 생성 제외를 기본 후보로 둔다. 기존 생존 개체를 갑자기 삭제하지 않으며 적힌 시간은 실제 웨이브가 아니다.
- [pool 제안] E05 계열 state 소비를 참조하되 E05 전역 warn/charge 상수를 바꾸지 않는다. 슬롯별 거리 상한·벽 충돌·취소 상태가 없으면 P2 보류한다.
- [구현 후보] `src/lib/enemySimulation.js`, `src/components/ZombieInstanceLayer.jsx`, `src/components/PooledEnemyVisuals.js`, `src/lib/enemyEntityPool.js`, `src/lib/burstEvents.js`.
- [개별 수용 제안] 선회 끝과 방향 표식 일치, solid 충돌 시 중지, 식판 장식과 몸통 피격 구분, generation 재사용 뒤 이전 돌진 소멸을 확인한다.
- [신규 자산 제안] 기존 트레이 형태를 재사용한 어깨 묶음과 장갑만 추가 후보다. 방패 면역·전면 피해 감소·추가 장비 파괴 시스템은 제외한다.

### 4.3 P2 선택 — 국자 투척수 `C4_LADLE`
- [목적 제안] E04 원거리 역할의 급식실 해석이다. 무한 장판을 까는 신종이 아니라 눈에 보이는 단발 음식 투사체로 제한한다.
- [실루엣 제안] 한 손의 긴 국자, 반대 손의 작은 통, 낮은 두건·보라회색 앞치마. B04보다 작은 머리 장비로 계층을 보존한다.
- [부품 제안] 일반 리그·국자 손잡이/볼·작은 통·두건. KitchenClutter 냄비와 기존 음식 투사체 외형을 우선 참조한다.
- [크기 제안] 높이 1.1 units/0.275 blocks, 장비 포함 폭 0.75/0.1875, 깊이 0.6/0.15; 몸통 반경 후보 0.28/0.07.
- [애니메이션 제안] 거리 유지→투사 방향 고정→국자를 어깨 위로 올림→한 번 내리며 발사→빈 국자를 낮추고 회복→거리 유지.
- [시간 제안] windup 1000ms, attack 150ms, recovery 1100ms. 발사 취소 때 투사체 생성 이벤트도 함께 취소한다.
- [공격 제안] 사거리 상한 후보 4 units/1 block의 단발; 폭발·지속 바닥 피해·느려짐은 없음. 수치상 피해/속도는 기존 실효값 확인 후 별도 승인한다.
- [대응 제안] 예고 때 측면 이동 또는 solid 뒤로 이동한다. LOS가 막히면 발사하지 않고 기존 회피/재탐색 규칙을 따른다.
- [편성 제안] 60~140초 후보의 기존 E04 요청 하나를 대체, 동시 최대 1체; P1과 독립적으로 선택 가능하다.
- [중첩 제안] B04 국물 예고·가마솥 마지막 3초 동안 새 발사 예고를 시작하지 않는다. 이미 발사된 투사체를 무통보 삭제하는 방식은 피한다.
- [pool 제안] E04 simulation·projectile pool·원거리 상한을 공유해야 한다. 새 투사체 pool로 기존 총량 제한을 우회하거나 무제한 타이머를 만들지 않는다.
- [구현 후보] `src/lib/enemySimulation.js`, `src/components/Enemies.jsx`, `src/components/ZombieInstanceLayer.jsx`, `src/lib/enemyEntityPool.js`, `src/lib/burstEvents.js`.
- [개별 수용 제안] 투사체 출발점과 국자 끝이 정렬되고, 벽/가구 차폐·비공격 clutter 통과·발사 1회·사망 취소·가마솥 경고 우선순위를 확인한다.
- [신규 자산 제안] 국자/작은 통만 추가 후보; B04 얼굴·모자·전용 국물 대폭발을 복제하거나 보스 전용 연출을 일반 적에게 배포하지 않는다.

### 4.4 P2 선택 — 청소 당번 `C4_MOP`
- [목적 제안] 바닥을 영구 변경하는 장판형이 아니라, 긴 걸레로 짧은 정면 쓸기를 수행하는 중거리 근접 역할이다.
- [실루엣 제안] 얇은 세로 몸통·비스듬한 긴 걸레·노란 고무장갑·작은 허리 양동이. 냉장고/선반 같은 직사각형 대형 실루엣을 피한다.
- [부품 제안] 일반 리그·걸레 봉/끝·양동이·장갑; 기존 통/잡동사니 형태와 toon 공유 재질을 우선 재사용한다.
- [크기 제안] 높이 1.2 units/0.3 blocks, 걸레 포함 폭 0.9/0.225, 깊이 0.7/0.175; 몸통 반경 후보 0.28/0.07.
- [애니메이션 제안] 끌고 걷기→두 손으로 봉을 가로 잡음→정면 낮은 쓸기→걸레를 회수하며 고개 숙임→걷기; 전 구간 장비 pivot을 명시한다.
- [시간 제안] windup 900ms, attack 250ms, recovery 1100ms; 예고 이후 회전 잠금으로 추적형 즉발 광역화를 막는다.
- [공격 제안] 전방 1.6 units/0.4 blocks 이내 낮은 부채꼴, 1회 피해 소비. 잔여 얼룩은 무해한 장식이며 둔화·미끄러짐·추가 collider 없음.
- [대응 제안] 뒤/옆으로 빠지거나 solid로 공격선을 끊는다. 걸레가 벽 너머로 보이더라도 반대편 플레이어를 맞히지 않는다.
- [편성 제안] 90~140초 후보에서 기존 근접 요청 하나를 대체, 동시 최대 1체; 다른 P2와 동시 채택은 별도 검토다.
- [중첩 제안] 가마솥 3초 경고·B04 격노/국물 경고에는 새 windup을 보류한다. 안전 통로를 걸레 장판으로 봉쇄하는 후속 확장은 제외한다.
- [pool 제안] 짧은 melee envelope를 공통화할 수 있을 때만 도입하며 개체별 임의 physics sensor·매 프레임 React state를 추가하지 않는다.
- [구현 후보] `src/lib/enemySimulation.js`, `src/components/PooledEnemyVisuals.js`, `src/components/ZombieInstanceLayer.jsx`, `src/lib/enemyEntityPool.js`, `src/lib/burstEvents.js`.
- [개별 수용 제안] 긴 봉 장식 때문에 몸통 피격이 커지지 않고, 경고 envelope·실제 쓸기·피해 영역이 일치하며, 얼룩이 경고 링과 혼동되지 않아야 한다.
- [신규 자산 제안] 걸레 끝·봉·장갑만 신규 후보다. 물 시뮬레이션·동적 바닥 shader·전역 이동 제어·새 상태이상은 추가하지 않는다.

## 5. Studio 연결과 사용자 명시값 불변
- [선독 완료] 기준 문서는 루트 `ZOMBIE_E01_STUDIO_TRANSFORM_CONNECTION_CODE.md` 전체다. 연구 폴더 사본만 보고 다른 변형 방식을 제안하지 않는다.
- [기존 계약] E01 item ID는 zombie-e01, 저장 키는 `zombie-e01::part::<숫자 경로>`이며 기존 E01에 studioPartId를 새로 주입하지 않는다[S15].
- [기존 계약] 기존 child index·part/group 키·리그 pivot·fill/outline 계층을 보존한다. P1 부품을 기존 E01 트리에 끼워 저장 경로를 이동시키지 않는다.
- [기존 계약] position/rotation은 최초 base에 offset을 더하고 scale은 base에 multiplier를 곱한다. 0/1/0 재입력은 base 복귀이며 새 절대 transform 경로로 대체하지 않는다[S15,S16].
- [보존] 애니메이션과 사용자 튜닝을 함께 소비하는 기존 계약을 따른다. idle 복귀·hit flash·outline 조정 때문에 사용자 위치/회전/크기를 재설정하지 않는다.
- [현행 우선] E01 연결 원문의 과거 localStorage 저장 예시는 구조 참고용이다. 현재 영속화는 Firebase-only이며 storage adapter는 오류로 거절된다[S16].
- [금지] localStorage·파일 프리셋·별도 DB를 Studio 영속화 대안으로 제안하지 않는다. 메모리 runtime dataset을 새 영구 저장소라고 표현하지 않는다.
- [사용자 불변] 명시된 수치·색·배치·얼굴·데칼을 ‘자동 최적화’하거나 현재 DB 미조회 상태에서 보정·마이그레이션·seed하지 않는다.
- [신규 연결 제안] 새 타입 채택 시 item ID·부품 트리·선택 경로를 먼저 문서 승인하고, 기존 transform 연결을 그대로 소비하는 preview/instance 대응만 검토한다.
- [수용 제안] 같은 Firebase revision에서 game·Studio·title의 해당 사용 화면을 비교한다. 새 적이 title 대상이 아니면 억지 노출하지 말고 기존 title 무회귀로 검증한다.
- [접근 금지] Three_Mini는 GraphicsStudio.jsx를 수정·포맷·복원·우회 위임하지 않는다. 필요성이 생기면 담당자에게 보고하고 해당 구현을 중단한다.
