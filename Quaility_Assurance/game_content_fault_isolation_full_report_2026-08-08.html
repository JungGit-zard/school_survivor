Executive summary

장애의 직접 원인은 대사/UI 텍스트가 JS locale 모듈 안에 직접 임베드된 구조에서 발생한 구문 오류였습니다. `src/lib/locales/ja.js`의 깨진 문자열이 Vite에서 Unterminated string로 판별되었고, `i18n.js`의 정적 import 경로를 통해 `App` 모듈이 차단되어 화면 렌더링 진입이 멈췄습니다.

이후 단일 구문 장애가 앱 기동 경로 전체로 전파된 구조적 이유는, 초기 진입부에서 i18n, quest/stage/weapon 데이터, Firebase/Studio getter까지 과다하게 묶인 설계였습니다. 교정은 대사 데이터 분리, 부트스트랩 복원력 강화, lazy 경계 확대, Studio 옵셔널 읽기 레이어 도입, 런타임 E2E/진단 경로 정리로 완결했습니다.

incident timeline

  1. 일부 일본어 대사 문자열이 JS 모듈 구문으로 손상됨.
  2. Vite 빌드에서 `Unterminated string`가 감지됨.
  3. `i18n.js`의 정적 import 경로가 App 기동 경로를 직접 차단.
  4. 초기화 실패 시 표시용 fallback가 없어 사용자가 빈 화면/진입 정체를 보게 됨.
  5. 장애 분석에서 progress getter, Studio strict read/write, 런타임 E2E 경로와의 병존을 확인.
  6. TSV 대사 분리, bootstrap 복구, lazy 분할, optional Studio reader 및 E2E 제거 반영.
  7. 검증: 130 passed(0 failed), production build pass, `/` 및 `/graphics-studio` 200 확인.

defect-by-defect analysis

1) Dialogue/UI source text in JS module — `src/lib/locales/ja.js`의 malformed 문자열로 모듈 파싱 실패.

2) Startup coupling — `main → App → ReadyGameApp → useGameStore → i18n` 및 콘텐츠/Studio 데이터 루트를 한 경로에 묶음.

3) Recovery absence — 최초 기동 예외에 대해 사용자에게 보이는 복구 UI가 부족.

4) Studio strict read coupling — 일반 게임 흐름에서 strict Studio getter가 hydration 유무와 무관하게 호출 가능.

5) progress getter exposure — `firebaseProgress` hydrated-only 접근이 reset/end/reward에서 예외 유발.

6) Runtime E2E 혼입 — 우회 라우트, diagnostics 라우트, `e2eAuth` 빌드 청크로의 경로가 남아 있었음.

7) Lazy chunk boundary miss — lazy 실패 시 local error boundary 미비.

8) Test expectation drift — seed 및 동기식 기대치가 lazy 전환으로 변경된 실제 모듈 구조와 정합되지 않음.
