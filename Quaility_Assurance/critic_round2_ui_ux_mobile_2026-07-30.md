## 남은 우선순위

### P0 — UI 8점 게이트를 실제 사용으로 검증하지 못함

- 영향: 코드상 접근성이 있어도 실제 사용자가 시작·중단·선택·결과 확인을 못 하면 릴리스 UI 품질을 주장할 수 없다.
- 누락: 320×568, 390×844, 412×915, 1280×720 각각의 로그인 signed-out/signing-in/signed-in, 첫 60초, 레벨업 3회, pause/resume, gameover 또는 clear 결과.
- 최소 다음 검증: 같은 빌드에서 위 장면을 캡처하고 각 핵심 터치 요소의 실제 bounding box(최소 44×44)와 safe-area 비겹침을 기록한다. DEV E2E라면 실제 Firebase를 건드리지 않는 현재 no-write 계약을 유지한다.

### P0 — 입력 접근성 전 흐름 미검증

- 영향: 마우스/터치만 되는 상태라면 키보드·보조기술 사용자와 데스크톱 사용자의 시작/긴급 pause/레벨업 선택이 끊긴다.
- 누락: 실제 `Tab`, `Enter`, `Escape`, `P`와 스크린리더로 로그인·동의·닉네임·pause·업그레이드·결과를 끝낸 기록. 현재 검사한 것은 focus-visible/ARIA 문자열과 일부 이벤트 단위 테스트뿐이다.
- 최소 다음 검증: 각 경로를 10회 반복해 성공/실패·포커스 순서·닫기 후 포커스 복귀를 표로 남긴다. 레벨업의 세 카드에서 이름과 효과가 읽히고 선택되는 것을 녹화 또는 접근성 트리 캡처로 남긴다.

### P1 — 모바일 레벨업과 결과 흐름의 실제 판독성 미확인

- 영향: 작은 화면에서 한 번의 업그레이드 오독이나 결과 후 막힘은 첫 플레이 재시도를 떨어뜨린다.
- 누락: 320px 카드 실제 줄바꿈/오버플로, 390/412px 카드 및 결과 화면, 실패/클리어 결과에서 로비/재시작 선택.
- 최소 다음 개선/검증: 먼저 현 구현을 바꾸지 말고 4개 해상도에서 3회 레벨업과 결과를 촬영한다. 실제 잘림이 보일 때만 카드 문구·행 높이 또는 결과 모달의 한 요소를 좁게 수정한다.

### P1 — 첫 게임 안내의 이해도 미측정

- 영향: 한 줄 가이드는 좋아졌지만 조이스틱/드래그가 실제로 첫 행동으로 이어지는지는 알 수 없다.
- 최소 다음 검증: 신규 E2E 상태에서 도움말을 열지 않은 사용자가 첫 이동과 첫 카드 선택까지 성공하는 관찰 시나리오를 추가한다. 일반 플레이어 흐름을 바꾸거나 Firebase 정본을 테스트 데이터로 사용하지 않는다.

### P2 — 정보 밀도와 읽기 크기

- 390×844 로비는 Stage 카드가 세로로 길고 하단 탭과 스크롤이 공존한다. 현재 캡처에서 즉시 실패는 아니지만, 412×915 및 보조기술 포커스 순서를 확인할 때 카드 잠금 설명·스크롤 위치·하단 탭 도달성을 함께 관찰해야 한다.
- 전투 HUD의 HP 수치·무기 아이콘·coin은 390×844에서 보이지만, 한 정지 장면만으로 저시력/큰 글꼴/접근성 확대를 통과시킬 수 없다.

## 통과까지의 가장 작은 순서

1. 코드 변경 없이 브라우저에서 4 해상도 × 로그인 3상태 × 주요 화면을 수집한다.
2. 핵심 터치(로그인/로그아웃, 게임 시작, Stage 입장, pause/재개, 3카드, 결과 CTA)를 실제로 10회씩 수행하고 44px·safe-area 측정을 남긴다.
3. 키보드 `Tab/Enter/Escape/P`와 스크린리더로 동일 흐름을 완료한다. 실패가 발생한 한 지점만 수정한 뒤 같은 증거를 다시 수집한다.
4. 결과 화면과 재도전까지 확인한 뒤에만 UI 종합 8점 이상을 재검토한다.
