## 초보자용 구분

**계정 해금**은 “이 무기가 내 도감에 등록되어 이후 게임에서 뽑힐 수 있다”는 뜻이다. 조건을 달성해도 손에 즉시 들리는 것은 아니다.

**런 중 획득**은 “이번 판 레벨업 카드에서 그 무기를 실제로 골랐다”는 뜻이다. 계정 해금 뒤에도 필요 레벨, 빈 무기 슬롯, 선행 무기 조건을 만족해야 한다.

**조합 발견**은 이번 판의 무기 조합으로만 열리는 발전 카드다. 하나코·바이키티 커터칼·선긋기는 계정 영구 해금 수와 분리한다.

## 현재 상태 요약

현재 카탈로그는 20종이다. 연필만 시작 장착이며, 13종은 STARTER라 계정에서 항상 열려 있고 7종만 기록 조건으로 잠겨 있다. 조건 배열은 모두 **OR**라서 하나만 만족하면 열린다. 레벨업은 현재 4개 선택지이며, 계정 잠긴 무기는 후보에서 제외한다.

문제는 STARTER 13종 때문에 수집 진행의 체감이 약하고, 한 판 조건은 도감에서 목표만 보이며, 기존 STARTER를 단순히 잠금으로 바꾸면 Firebase 플래그가 없어 기존 유저 권리가 사라진다는 점이다.

## 해금 흐름

```text
실제 적 처치·골드·생존·클리어
  → 런 종료에서 이번 런 요약 + Firebase 누적 records 평가
  → 새 무기 ID만 weaponUnlocks에 자동 추가
  → 결과창 “새 무기 해금”
  → 로비 무기 도감에서 확인
  → 다음 런의 레벨업 4선택지에서 조건 충족 시 획득 카드 등장
```

- 같은 런에서 여러 조건을 달성하면 해당 무기를 모두 자동 지급하되, 이미 해금된 무기는 다시 보상하지 않는다.
- 하나코와 바이키티 커터칼의 최근 1회 보장 규칙은 그대로 유지한다. 선긋기는 현재처럼 조합 조건만 적용하며 별도 확정 등장은 이번 범위에서 추가하지 않는다.
- 무기 보유 상한, 최소 레벨, 강화 규칙, 보스 패시브 효과는 이 기획의 변경 대상이 아니다.

## UI 레이아웃 확정 범위

1. 로비 하단의 기존 `무기` 버튼을 도감 진입점으로 유지한다. 새 해금이 있으면 작은 NEW 배지를 붙이고, 도감을 확인하면 배지만 지운다.
2. 무기 도감은 해금 수, 전체/해금/잠김/이번 해금 필터, 아이콘 또는 공통 실루엣, 역할 한 줄, 정확한 계정 조건을 보인다.
3. 잠긴 계정 무기는 누적 조건만 `현재/목표` 진행 막대를 보인다. 한 판 조건과 조합 조건은 목표/선행 무기만 보여 준다.
4. 결과창은 새 무기 이름·해금 이유·`무기 도감 보기`를 제공한다. 저장 실패는 “저장하지 못했습니다. 이번 플레이는 계속됩니다.”라는 비차단 안내만 한다.
5. 코인 상점의 잠긴 영구 강화 항목은 `해금 조건 보기`로 도감 상세에 이동한다. 퀘스트 가방은 보스 패시브/퀘스트 전용으로 유지한다.

현재 HUD의 **4열 레벨업 카드**를 유지한다. UI 문서가 제안한 모바일 2×2는 별도 미승인 후속안이며, 현재 구현 또는 이번 해금 체계의 자동 변경으로 취급하지 않는다.

## Firebase 정본과 저장 실패

|데이터|용도|정본 여부|
|---|---|---|
|`progress.records`|누적 런·처치·골드·생존·클리어·보스 처치 사실|정본|
|`progress.weaponUnlocks[id] = 1`|계정 무기 영구 권리|정본|
|`weaponUnlockSchemaVersion`|기존 유저 권리 이전 완료 버전|도입 시 정본|
|결과창 신규 목록/NEW 읽음 상태|이번 화면 피드백|권리와 분리, 필요할 때만 추가|

- 해금과 진행은 Firebase에만 저장한다. `localStorage`, IndexedDB, URL, 임시 JSON의 해금 저장·복원 계획은 현 프로젝트 정책상 **폐기**한다.
- Firebase hydrate 전 또는 저장 실패 시 게임·기존 도감·레벨업은 멈추거나 숨지 않는다. 단, 영구 저장 성공을 주장하지 않고 저장 불가 안내를 보인다.
- QA 문서의 RTDB transaction 및 `recentRunIds`(동일 런 중복 가산 방지)는 다기기/재시도 안전성을 높이는 **별도 기술 권고**다. 데이터 구조와 규칙 변경을 수반하므로 사용자 승인 없이 이번 무기 기획 구현에 포함하지 않는다.

## 기존 유저 이전

현재 STARTER 13종은 Firebase `weaponUnlocks`에 플래그가 없다. 이들 중 기본군 이외를 잠금으로 전환하려면 다음 순서를 반드시 지킨다.

1. 기존 STARTER 권리를 Firebase unlock map에 한 번 합집합으로 추가한다.
2. `weaponUnlockSchemaVersion`을 기록하고, 신규 계정 생성 때도 현재 버전을 기록한다.
3. 그 뒤 카탈로그 STARTER를 축소한다.

이전은 값 추가만 하며 기존 unlock map을 삭제·덮어쓰지 않는다. 과거 유저는 과거에 쓸 수 있던 무기를 잃지 않는다. 조합 3종은 계정 flag가 아닌 런 조건이므로 별도 권리 이전 대상이 아니다.

## 작은 구현 순서 (vertical slices)

1. **정의와 순수 평가**: 20종 조건표와 기본군을 카탈로그에 반영하고 조건 경계값 테스트를 만든다.
2. **기존 유저 보호**: Firebase 스키마 버전, 단방향 legacy entitlement 이전, 신규 계정 분기를 구현하고 복원 테스트를 통과한다.
3. **런 종료 자동 지급**: 실제 런 요약에서 중복 없는 unlock diff를 저장하고 결과창 피드백을 연결한다.
4. **도감/상점 연결**: 조건·진행·조합 표기를 추가하고 잠긴 강화 항목을 도감으로 연결한다.
5. **별도 후속 강화**: 다기기 transaction ledger, UI 2×2 전환, NEW 읽음 영구화처럼 별도 승인이 필요한 항목을 분리한다.

## 수용 기준

- 새 계정은 기본군 4종만 계정 해금 상태이며, 연필로 시작한다.
- 각 확정 조건은 경계값에서 한 번만 무기를 해금하고, 다음 런의 4선택지 후보가 된다.
- 조합 3종은 계정 unlock flag 없이 해당 런의 선행 무기와 레벨을 만족할 때만 나온다.
- 기존 유저는 배포 전 사용 가능 무기를 하나도 잃지 않는다.
- Firebase 재로그인 뒤 계정 권리와 누적 기록이 복원된다. 저장 실패는 플레이를 중단시키지 않는다.
- 브라우저 영구 저장소로 해금을 저장하거나 복원하지 않는다.
- 타이틀, 그래픽 Studio, 보스 패시브, Stage 4 바닥, 이누콘 자산은 변경하지 않는다.

기본군 4종, 위 표의 개별 수치, 기존 유저 권리 전부 보존, 현재 HUD 4열, 핵심 구현은 2026-08-22 사용자 승인으로 확정됐다. 개발 전체해금 치트의 출시 격리 방식과 transaction/recentRunIds 도입은 여전히 별도 미승인 비범위다. 모바일 2×2 전환도 별도 승인 없이는 구현하지 않는다.
