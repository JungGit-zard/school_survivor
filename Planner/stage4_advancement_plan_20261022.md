## 1. 결론과 변경 경계

현재 급식실의 재료는 충분하다. 중앙 가마솥, 동·북쪽 조사 동선, 원거리 사격과 돌진을 전환하는 주방장을 **읽고 선택할 수 있는 전투**로 연결하는 것이 고도화의 핵심이다.
전역 HP·스폰 증가나 신규 보스 추가보다, 기존 위험의 겹침과 이동 탈출로를 먼저 검증한다. Stage 1 모바일 플레이 루프 안정화가 제품 우선순위이며, 본안은 그 작업을 밀어내는 구현 지시가 아니다.
이 문서는 기획만 한다. 코드·모델·자산·Firebase·배포·브라우저를 변경하거나 실행하지 않았다. 아래 실행 체크리스트는 후속 승인 범위다.
새 수치가 있는 항목은 `PROPOSAL`이며 오너 확정값을 덮어쓰지 않는다. 기존 수치는 `SOURCE DEFAULT`로 구분하며 실제 Firebase/운영 실효값이라고 주장하지 않는다.

- 오너 확정: Stage 4는 Stage 3 보스 처치만으로 즉시 영구 해금한다.
- 오너 확정: Stage 5는 Stage 4 보스 처치만으로 즉시 영구 해금한다.
- 탈출·생존시간·퀘스트·추가 확인 버튼은 해금의 선행 조건이 아니다. 해금과 다음 판으로의 화면 전환은 별개다.
- 유지: 명목 240초, B04 150초, 마틸다 예고 205초/등장 210초, 포탈 210초. 자동 승리를 추가하지 않는다.
- 타이틀 문구·UI·모델·배경·음악·공유 연결은 잠금 유지. 이 기획을 타이틀 개선 권한으로 해석하지 않는다.
- Studio 입력의 저장·조회 정본은 Firebase다. 로컬 시드·localStorage·복구 fallback을 제안하지 않는다. 저장 실패로 기존 그래픽을 숨기지도 않는다.

## 4. Stage 4 정체성과 네 단계 학습

정체성은 “피할 곳이 전혀 없다”가 아니라 **“가마솥의 주기를 읽고 사선을 끊은 뒤, 빈 방향으로 이동한다”**다. 안전한 선택이 남아 있어야 숙련의 의미가 생긴다.
이하 네 단계는 Stage 4 내부 학습 단계이며 Stage 1~4의 구현을 다시 설계하는 표가 아니다.

| 학습 단계 | 체험과 판단 | 성공의 관찰 기준 |
|---|---|---|
| ① 방향 읽기 | 남쪽 시작 → 중앙 가마솥 주기 → 동·서 통로 중 선택 | 첫 폭발을 본 뒤 위험 밖으로 이동하는 경로를 설명할 수 있음 |
| ② 경로 선택 | E04 사선·E05 돌진 사이에서 외곽 조사와 전투를 선택 | 퀘스트를 포기해도 생존/해금에 손해 조건이 붙지 않음 |
| ③ 패턴 전환 | B04 포격 → HP 임계 국물 → 돌진 | 기존 예고에서 위험 지점과 이동 방향을 구별하고 후딜에 반격 |
| ④ 목적 선택 | 보스 처치 영구 해금과 210초 포탈 탈출을 구별 | 보스 사망 후 다음 stage 해금 유지, 포탈 대기는 선택으로 이해 |

새 강제 튜토리얼·조작 잠금은 넣지 않는다. 기존 상호작용/위험 표현이 이 학습을 전달하는지 먼저 관찰하며, 설명 부족은 gameplay 내 안내 후보로만 인계한다.
학습 성공률·이탈률은 현재 측정값이 없다. 위 문장은 설계 의도이며 실제 플레이 평가가 아니다.

## 5. 급식실 공간과 읽을 수 있는 동선

좌표 표기: `(X,Z)` world units / blocks, `1 block = 4 units`. 물리 반경과 카메라 투영을 혼동하지 않는다. 장식 타일 하나를 block 하나로 세지 않는다.
SOURCE DEFAULT: 전체 18.72 × 32 units / 4.68 × 8 blocks, 반폭 9.36 × 16 units / 2.34 × 4 blocks.
바닥 타일은 0.8 units / 0.2 blocks다([ClassroomFloor L21–33, L52–58](../Developer/r3f_prototype/src/components/ClassroomFloor.jsx#L21-L58)). 새 바닥 설계는 범위 밖이다.

```text
북(-Z)     냉장고       쿡라인(가스 완료)       싱크(손잡이)
           서쪽 우회          북쪽 연결          조리부 학생
서(-X)     외곽 회귀     [중앙 가마솥 위험]      동쪽 조리대(명단)   동(+X)
                           남쪽 시작            급식 당번 학생
남(+Z)                    배식대 / 복귀 동선
```

- 중앙 가마솥 `(0,0)` units / `(0,0)` blocks와 남쪽 시작 `(0,7)` units / `(0,1.75)` blocks를 유지한다.
- 남쪽 당번 `(2.28,11.65)` units / `(0.57,2.9125)` blocks → 동 조리대 `(6.96,-3.9)` units / `(1.74,-0.975)` blocks → 당번 복귀가 첫 선택 동선이다.
- 조리부 학생 `(4.95,-6.2)` units / `(1.2375,-1.55)` blocks → 북동 싱크 `(4.45,-13.72)` units / `(1.1125,-3.43)` blocks → 쿡라인 `(-0.39,-13.75)` units / `(-0.0975,-3.4375)` blocks가 두 번째 동선이다.
- 상기 좌표는 authored 기본 배치다. 실제 조사 접근 지점·몸체 폭·회전·Studio 변경을 반영한 안전 경로 길이는 아직 측정하지 않았다.

근거: [배치 L460–530](../Developer/r3f_prototype/src/components/StageObjects/stageObjectPlacements.js#L460-L530), [동 조리대 L546–553](../Developer/r3f_prototype/src/components/StageObjects/stageObjectPlacements.js#L546-L553), [가마솥·학생 L725–750](../Developer/r3f_prototype/src/components/StageObjects/stageObjectPlacements.js#L725-L750).
문두의 “전부 시각 전용” 주석만 믿으면 안 된다. 대형 주방 타입은 차단 집합에 있고 실제 collider는 blocking 플래그를 해석한다([colliders L24–35, L415–423](../Developer/r3f_prototype/src/components/StageObjects/stageObjectColliders.js#L415-L423)).
배치 해석에는 중앙 가마솥 강제 보존과 과거 폭의 X 변환도 있다([placements L770–789](../Developer/r3f_prototype/src/components/StageObjects/stageObjectPlacements.js#L770-L789)). 따라서 원문 좌표만으로 운영 통행 가능을 확정하지 않는다.

PROPOSAL: 현재 위치를 유지한 채 중앙 좌·우 우회와 북쪽 연결의 유효 통로를 측정한다. 통로 폭 목표 후보는 2.4 units / 0.6 blocks 이상이며, 보스·좀비 몸체와 회전 접촉을 포함해 확정한다.
목표 미달 시 모든 소품을 밀거나 없애지 않는다. 막히는 collider/접근면만 특정해 Studio 담당에게 전달하고, 승인된 최소 배치 변경만 별도 수행한다.
가마솥 폭발 반경 3.2 units / 0.8 blocks 바깥이라고 자동으로 안전하지 않다. 사선·몸막힘·돌진 접근이 겹치는지 함께 본다.

## 14. 결정 요청과 완료 정의

Advisor의 권고 순서는 **P0 진행도 불일치 확인 → 기존 위험/통로 재현 → P1 국소 공정성 → 필요할 때만 P2**다. 지금 승인할 새 전역 난이도 수치는 없다.
실제 Firebase/모바일 상태, 원격 추적 참조 이후 변경, W/R 통합 여부가 남은 불확실성이다. 소스 조사만으로 “현재 서비스에서 잘 된다/고장 났다”라고 확정하지 않는다.
이번 산출물의 완료는 문서·근거 링크·조사 해시 확인이다. 게임플레이 QA·빌드·성능·저장 검증 완료가 아니며, Main Advisor의 독립 검토가 후속 단계다.
