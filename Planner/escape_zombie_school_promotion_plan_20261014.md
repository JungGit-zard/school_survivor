# 탈출 좀비학교 홍보 실행안

기준일 2026년 10월 14일 · 실행 담당 개발자 Terry · 무료 플레이테스트 모집

홍보의 목표는 낯선 사람이 게임에 방문하고, Google 로그인 뒤 실제로 한 판을 시작하고, 다시 돌아오는 것이다. 첫 메시지는 **“연필로 좀비학교에서 60초만 버텨 주세요. 개발자가 첫인상을 기다립니다.”**로 통일한다. 60초는 첫 플레이를 부탁하는 기준이며 별도 게임 모드나 스테이지 종료 시간이 아니다.

처음 7일은 기존 블로그 자산과 실제 플레이 영상으로 적은 수의 피드백을 모은다. 규칙을 확인한 게시처에만 올리고, 조회수보다 실제 시작과 재방문을 기록한다. 이 실행안 작성으로 게시·광고 집행·예약 변경·측정 복구가 수행된 것은 아니다.

## 1 게임 소개와 약속 범위

**탈출! 좀비학교는 학교에서 몰려오는 좀비를 피하며 자동 공격과 레벨업 카드로 성장하고 탈출을 노리는 생존 액션 게임이다.** 연필·자·텀블러 같은 생활용품이 무기가 되고, 친구를 돕는 퀘스트와 동료가 학교라는 배경에 의미를 더한다. 공포만 강조하기보다 익숙한 학용품의 엉뚱함과 아슬아슬한 회피 장면을 보여 준다.

| 항목 | 홍보에 쓸 표현 | 구분할 사항 |
| --- | --- | --- |
| 가격 | 무료, 게임 내 광고와 유료 구매 없음 | 유료 홍보비와 게임 안의 결제는 별개다. BM은 수익을 내는 구조를 뜻하며 이 계획에는 새 BM을 넣지 않는다. |
| 웹 | 설치 없이 브라우저에서 플레이 | 시작 전 Google 로그인이 필요하다. “무가입”, “로그인 없이 즉시 플레이”라고 쓰지 않는다. |
| 조작 | 이동하면서 피하고 공격은 자동, 레벨업 때 카드 선택 | 모바일 조작·기기별 성능은 실제 대상 기기의 확인 범위로 안내한다. |
| 학교 | 교실·복도·체육관·급식실에서 생존과 탈출 | 세부 수치·등장 시각은 배포 상태 확인 없이 약속하지 않는다. |
| 성장 | 이번 판의 카드 선택, 플레이로 얻는 골드와 성장 | 현금 결제나 광고 시청을 성장 조건으로 표현하지 않는다. |
| 첫 도전 | 먼저 60초 생존에 도전해 주세요 | 60초 전용 모드, 60초 클리어 보상, 새 이벤트를 만든 것이 아니다. |
| 랭킹 | 기록을 확인하며 다음 도전에 활용 | 3개 탭과 누적랭킹 기본 선택, 0점 기록 요청은 구현 검토 중이며 미배포다. 제공 중이라고 쓰지 않는다. |

게스트 진입이나 타이틀 개선은 별도 제안으로만 남긴다. 이 홍보안을 이유로 로그인·타이틀·게임·Firebase 데이터를 변경하지 않는다. 기존 전체 게임 가이드에 남은 게스트 설명보다 현재 확인된 로그인 필요 조건을 따른다.

웹 플레이는 [https://escapezombie.com/game](https://escapezombie.com/game)를 기본 목적지로 사용한다. [공식 첫 화면](https://escapezombie.com/)과 [소개 페이지](https://escapezombie.com/landing)는 설명이 필요할 때 보조 링크로 쓴다. Android 링크는 프로젝트 기존 문서의 [Google Play 등록 주소](https://play.google.com/store/apps/details?id=com.jungyoon.zombieschool)를 사용한다. 공개 배포 트랙과 이용 가능 국가 확인 전 “누구나 설치 가능”이라고 단정하지 않는다.

첫 주에는 한국어 플레이테스터를 우선한다. 영어 게시문은 해외 피드백 모집에 쓰되 같은 영상·같은 문제 질문으로 비교한다. 개발자 커뮤니티의 호평이 일반 플레이어의 재방문을 대신하지 않으므로 두 집단을 따로 기록한다.

## 4 게시처 주소와 현행 규칙

확인일은 2026년 10월 14일이다. “확인됨”은 공개 규칙을 읽었다는 뜻이며 해당 계정의 게시 승인이나 게임의 진입 성공까지 보장하지 않는다. 게시 직전 고정 공지를 다시 읽고 현재 계정의 자격을 확인한다.

| 게시처와 정확한 주소 | 확인된 규칙 | 실행 판단 |
| --- | --- | --- |
| [디시 인디 게임 개발 갤러리](https://gall.dcinside.com/mgallery/board/lists/?id=game_dev) | 2026년 10월 6일 최신 공지는 홍보·테스트 성격의 글에 일지탭 글 5개 이상을 전제로 한다. 홍보탭이 HIT탭과 통합되었다고 안내한다. | 기존 계정의 개발일지 5개 충족 확인 전 홍보글 보류. 갯수를 채우려는 빈 글 도배 대신 실제 개발 과정만 기록한다. |

| [국내 웹게임 게시처 검토 예시 겜마니오락실](https://www.fungame.pe.kr/) | 신규 개발자 게임 접수 창구·규칙을 확보하지 못했다. | 게시 가능한 곳으로 간주하지 않는다. 담당자의 접수 안내가 확인될 때만 제휴 후보로 검토한다. 초기 실행 채널에서 제외한다. |

국내 개발갤은 오래된 공지의 “홍보 말머리”만 보고 게시하면 최신 규칙과 어긋난다. [2026년 10월 6일 공지](https://gall.dcinside.com/mgallery/board/view/?id=game_dev&no=229623&page=1)의 일지 5개 조건을 먼저 적용하고 [기본 규칙](https://gall.dcinside.com/mgallery/board/view/?id=game_dev&no=174286)도 함께 확인한다. Reddit 기준은 [공식 규칙 JSON](https://www.reddit.com/r/playmygame/about/rules.json)을 근거로 한다.

커뮤니티별 허용 시간이나 횟수를 추측해서 만들지 않는다. 확인이 끝나면 채널 기록에 계정, 게시판, 읽은 공지 URL, 확인 시각, 다음 게시 가능일을 적는다. 삭제된 글을 곧바로 재게시하거나 추천·조회수를 구매하지 않는다.

## 5 기존 블로그 자산과 검색 유입

현재 원고 제목은 **“연필 하나 들고 좀비학교 탈출! 개발 중인 게임을 테스트해 주실 분을 찾습니다”**다. 기존 원고의 자동 공격, 학용품 무기, 동료, 학교 공간, 친구의 부탁, 두 종류 성장 설명을 재사용한다. 게임가이드 기준의 무기·퀘스트 갯수는 배포 확인 없이 새 글의 핵심 약속으로 내세우지 않는다.

| 기존 파일 | 재사용 방법 |
| --- | --- |
| `Graphic_designer/blog_tistory_20261011/tistory_body.html` | 긴 소개 글의 본문과 첫인상 질문. 실제 게시 주소는 별도 확인해 기록한다. |
| `Graphic_designer/blog_tistory_20261011/title.txt` | 소개형 제목으로 보관하고, 후속 글은 첫 판·무기·카드 선택처럼 하나의 주제로 쓴다. |
| `Planner/escape_zombie_school_complete_guide_20261011.html` | 게임 이해를 위한 내부 참고. 로컬 소스와 실제 배포의 차이를 구분한다. |
| 기존 콘셉트 이미지 | 학교 분위기 설명에 사용하고 “콘셉트 아트이며 실제 게임 화면이 아닙니다” 표기를 유지한다. |

검색용 후속 글은 **“무료 웹 좀비게임 탈출 좀비학교 첫 플레이 방법”**을 후보 제목으로 잡는다. 첫 문단에 무료·설치 불필요·Google 로그인 필요를 함께 적고, 실제 조작과 카드 선택 스크린샷 뒤에 플레이 링크를 둔다. “웹 좀비게임”, “생존 액션”, “학용품 무기”, “인디게임 플레이테스트”를 자연스럽게 사용하며 동일 문구를 반복하지 않는다.

글의 순서는 한 줄 소개 → 시작 전 로그인 안내 → 이동과 자동 공격 → 카드 선택 예시 → 첫 60초에서 관찰할 점 → 기기·브라우저를 포함한 피드백 요청이다. 기존 소개 글에서 후속 글로, 후속 글에서 기존 소개 글로 연결하되 실제 게시 URL을 확인한 뒤 넣는다. 검색 노출은 당일 보장하지 않는다. 7일·30일에 검색어 유입과 실제 시작을 함께 본다.

## 8 영상 촬영과 플레이 연결

실제 게임 화면을 세로 영상으로 보여 준다. 콘셉트 이미지를 플레이 영상으로 다루지 않고, 화면에서 보이는 조작과 결과만 설명한다. 촬영을 위해 모델·타이머·난이도·음원을 변경하지 않는다. Google 이메일 주소 등이 보이는 로그인 화면은 소재에 넣지 않는다.

| 15초 버전 | 영상 | 화면 문구 |
| --- | --- | --- |
| 0〜2초 | 연필 공격과 적이 몰리는 장면 | 연필로 좀비학교에서 버틸 수 있을까 |
| 2〜6초 | 좁아지는 공간에서 회피 | 이동으로 피하고 공격은 자동 |
| 6〜10초 | 카드 선택과 다음 공격 | 카드 한 장으로 이번 판을 바꿔 보세요 |

| 13〜15초 | 실제 게임 장면 위 CTA | 무료 웹 플레이 · Google 로그인 필요 · 프로필 링크 |

| 30초 버전 | 영상 | 화면 문구 |
| --- | --- | --- |
| 0〜3초 | 인상적인 연필 또는 텀블러 공격 | 학용품으로 좀비학교를 탈출한다면 |
| 3〜8초 | 이동과 자동 공격 | 피하는 건 직접, 공격은 자동 |

첫 3편은 `pencil_60s`, `tumbler_escape`, `card_choice`로 구분한다. 같은 게임 영상에 첫 2초 문구만 바꾸는 비교는 가능하지만 언어·영상 길이·게시 시간까지 동시에 바꾸면 무엇이 영향을 줬는지 알기 어렵다.

YouTube Shorts 설명과 댓글의 일반 URL은 클릭되지 않는다. **“프로필 링크에서 플레이”**를 CTA로 쓰고 채널 프로필 링크에 §10 YouTube URL을 넣는다. 관련 동영상 링크 기능은 외부 웹 링크가 아니라 자신의 채널 영상으로 연결한다. 짧은 조작 설명 영상을 관련 동영상으로 연결하는 방법은 보조 선택지다. 긴 영상 설명의 외부 링크는 고급 기능 이용 자격이 필요하다. [YouTube 링크 안내](https://support.google.com/youtube/answer/13748639?hl=ko), [관련 동영상 안내](https://support.google.com/youtube/answer/14075157?hl=ko)

Instagram Reels에도 캡션 URL 클릭을 전제로 설계하지 않고 프로필 링크를 사용한다. 계정에서 제공하는 실제 링크 기능을 확인한 후 안내한다. 영상에는 프로필 화면의 버튼을 정확히 적고 게시 뒤 링크를 직접 열어 확인한다.

## 9 크리에이터 요청과 플랫폼 등록 검토

## 10 채널별 링크와 UTM 사용

UTM은 링크 끝에 붙이는 유입 이름표다. 사용자의 게임 값을 바꾸는 기능이 아니며 링크를 만들었다고 분석 데이터가 자동으로 검증되는 것도 아니다. `/game`을 직접 목적지로 잡아 소개 페이지에서 한 번 더 눌러야 하는 단계를 줄인다.

| 파라미터 | 쉬운 뜻 | 예시 |
| --- | --- | --- |
| `utm_source` | 어느 채널에서 왔나 | `tistory`, `youtube`, `reddit` |
| `utm_medium` | 어떤 방식의 유입인가 | `blog`, `social`, `community`, `referral` |
| `utm_campaign` | 어떤 모집 활동인가 | `playtest_202610` |
| `utm_content` | 어떤 글이나 영상인가 | `pencil_60s_ko`, `card_choice_en` |

같은 글의 링크 이름은 게시 후 바꾸지 않는다. source는 소문자 영문으로 통일하고 이름·이메일·UID·토큰을 넣지 않는다. Short의 공용 프로필 링크는 여러 영상이 함께 쓰므로 그 링크만으로 특정 영상의 성과를 정확히 나눌 수 없다. 영상별 클릭을 분리할 수 없으면 채널 단위 성과로 적는다.

기존 자동화의 링크를 이 표만 보고 교체하지 않는다. 새 수동 홍보나 별도 승인된 편집에서 사용한다. 실제 로그인 복귀와 화면 이동 후 UTM이 분석에 어떻게 남는지는 측정 검증 과제로 둔다. 브라우저 localStorage로 UTM이나 로그인 상태를 저장하지 않는다.

## 11 측정 상태와 성과 계산

KPI는 목표를 확인하는 숫자다. 여기서는 **방문 → 로그인 성공 → 실제 판 시작 → 첫 판 60초 → 재방문**을 차례로 본다. 모든 비율은 같은 기간·같은 유입·같은 신규 이용자 집단으로 계산한다. 개발자와 테스트 도구의 접속은 따로 표시한다.

현재 웹 배포의 측정 ID는 `G-HZ3LTGHV6F`다. 연결 속성은 `541779330`, 계정은 `332638246`, 웹 스트림은 `15119854600`, Android 스트림은 `15200017955`로 확인되어 있다. 스트림은 웹과 앱이 데이터를 보내는 각각의 통로다. **ID와 연결 정보 확인은 이벤트 송신·대시보드 수집 정상 확인이 아니다.** 실제 성과는 아직 실시간 수집과 이벤트 내용 확인이 필요하다. [해당 GA 속성 열기](https://analytics.google.com/analytics/web/#/p541779330/reports/intelligenthome)

| 로그인 후 시작률 | 첫 판 시작 신규 이용자 ÷ 로그인 성공 신규 이용자 × 100 | 로그인과 실제 플레이를 혼동하지 않는다. |
| 첫 60초 도달률 | 첫 판에서 60초 생존한 신규 이용자 ÷ 첫 판 시작 신규 이용자 × 100 | 게임 시계 기준 생존이며 일시정지·카드 선택 시간을 포함한 웹 체류 60초와 다르다. |
| 두 번째 판 비율 | 같은 날 두 번째 판을 시작한 신규 이용자 ÷ 첫 판 시작 신규 이용자 × 100 | 첫인상이 다시 해 보고 싶게 했는지 본다. |
| D1 재방문율 | 첫 플레이 다음 날 다시 방문한 이용자 ÷ 추적 가능한 첫 플레이 이용자 × 100 | D1은 다음 날이다. 방문 복귀와 판 시작 복귀를 따로 기록한다. |
| D7 재방문율 | 첫 플레이 7일 뒤 다시 방문한 이용자 ÷ 추적 가능한 첫 플레이 이용자 × 100 | 측정 가능한 동일 집단에서만 계산한다. |
| 탈출 성공률 | 탈출 완료 판 수 ÷ 시작 판 수 × 100 | 이용자 전환율과 구분하고 진행 중인 판은 기간 경계 처리 기준을 정한다. |

분모가 0이면 0% 대신 “계산 불가”라고 적는다. 식별 기준이 없거나 수집이 누락되면 “미측정”으로 적고 추측으로 채우지 않는다. Firebase 랭킹 기록 수를 전체 방문자수로 사용하지 않는다.

### 측정 준비와 확인 순서

1. 현재 이벤트 정의를 읽어 방문·로그인 시도·성공·실제 판 시작·게임시간 60초·판 종료를 어떤 이벤트와 조건으로 볼지 대응표를 만든다. `app_open`, `login_state`, `level_start`, `run_checkpoint`, `level_end` 같은 이름만으로 의미가 충족됐다고 판단하지 않는다.
2. 태그와 이벤트의 실제 네트워크 송신, GA 실시간 또는 DebugView 수집, UTM source·campaign을 확인한다. DebugView는 시험 이벤트를 실시간으로 보는 화면이다. 게임 체크포인트가 정확히 60초인지 별도 확인한다.
3. 실제 대상 환경의 새 세션에서 로그인과 핵심 진입이 끝까지 되는지 검증한다. 현재 문서 작성 단계에서는 실행하지 않았으며, 실제 Firebase 값을 건드리는 테스트라면 프로젝트의 초기 스냅샷·완전 복원 규칙을 먼저 충족한다.
4. 필요한 이벤트가 없으면 계측 작업을 별도 요청으로 분리한다. 인증 토큰·이메일·개인정보를 이벤트에 넣지 않고, 동의와 개인정보 고지를 확인한다. 관측이 불가능한 재방문은 수동 자발적 피드백과 구분한다.

매일 기록 칸은 `날짜 / 채널 / 게시 URL / 소재 / 노출 / 링크 클릭 / 방문 / 로그인 시도·성공 / 첫 판 / 60초 / 두 번째 판 / 다음 날 복귀 / 주요 피드백 / 미측정 항목`이다. 플랫폼 클릭 수와 GA 방문 수는 집계 방식이 달라 일치한다고 가정하지 않는다. [Firebase 웹 분석 시작](https://firebase.google.com/docs/analytics/web/get-started), [GA DebugView](https://support.google.com/analytics/answer/7201382?hl=ko)

유료 홍보는 사용자 승인과 예산이 필요한 선택지다. 지금 집행액은 이 작업 기준 **0원**이며, 무료 홍보가 실제 시작을 만든 소재와 정확한 측정이 확보된 뒤에만 검토한다. YouTube Promote 또는 소규모 크리에이터 협업 중 하나를 후보로 두고 대상·기간·총 청구 상한·세금·중단 조건을 승인받는다. 두 가지를 동시에 시작하지 않는다.

기존 2026년 10월 3일 계획의 하루 실제 청구 10,000원 이하 한도는 예산 비교 참고이며 새 집행 승인이 아니다. 평균 일예산과 실제 하루 청구 상한은 다를 수 있으므로 계정의 결제·세금·지출 규칙을 확인한다. 60초 도달자가 0이면 관련 비용 지표를 계산 불가로 적고 확대하지 않는다. 유료 사용자를 데려오는 비용은 `광고비 ÷ 실제 신규 판 시작자`, `광고비 ÷ 60초 도달 신규 이용자`로 따로 계산한다. 게임에 광고나 유료 구매를 추가하는 제안은 포함하지 않는다.

## 15 게시 점검과 출처

게시 직전에 다음을 확인한다.

- 무료와 게임 내 광고·유료 구매 없음, 시작 전 Google 로그인 필요가 함께 적혀 있다.
- 60초를 별도 모드·클리어 시간·보상으로 약속하지 않는다.
- 보여 주는 플레이 장면은 실제 게임이며 콘셉트 이미지에는 구분 표기가 있다.
- 현재 미배포 랭킹 요청과 미검증 계측을 제공 완료로 쓰지 않는다.
- 채널 공지와 게시 자격을 충족하고 UTM과 목적지 링크가 맞다.
- 실제 게시 URL·시각을 남긴다. 버튼 클릭 기록과 공개 게시 확인은 구분한다.
- 기존 예약·타이틀·로그인·게임·Firebase 정본을 이 홍보안만으로 변경하지 않는다.
