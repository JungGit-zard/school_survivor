# 무기 해금 체계 기획안

- 작성일: 2026-08-22
- 상태: **추천안**. 사용자가 아직 해금 수치·보상 속도를 확정하지 않았으므로 아래 값은 구현 전 확정이 필요하다.
- 범위: 계정 단위 무기 해금. 한 판 안에서 카드를 뽑아 무기를 획득하는 `minLevel`/선행 무기 조건과 구분한다.
- 현재 코드 기준: `src/lib/weaponCatalog.js`, `src/lib/upgrades.js`, `src/lib/weaponPermanentUpgrades.js`, `src/store/useGameStore.js`.

## 용어와 원칙

- **계정 해금**: Firebase 진행도의 `weaponUnlocks`에 영구 기록되어, 이후 모든 런에서 해당 획득 카드가 후보가 되는 상태다.
- **런 중 획득**: 이번 판의 플레이어 레벨이 `minLevel`에 도달한 뒤 레벨업 카드로 무기를 선택하는 일이다. 계정 해금만으로 즉시 장착되지 않는다.
- **무기 조합**: 계정 해금이 아니라 이번 런에서 선행 무기를 실제 보유했을 때만 나타나는 발전 카드다.
- 해금은 되돌리지 않는다. 새 체계 적용 뒤에도 기존 유저가 과거에 사용 가능했던 무기를 잃지 않는 것이 우선이다.

## 현재 체계의 확인된 문제

1. 20종 중 13종이 STARTER다. 실제 계정 해금 진행은 7종뿐이라 무기 도감의 잠금/해금 경험이 약하다.
2. `evaluateUnlocks`는 조건 배열의 첫 성공으로 해금하므로, 화면의 “아무 조건 하나 달성” 표기와 맞지만 `Stage 1 클리어 또는 8런`처럼 서로 다른 난이도의 우회 조건이 섞여 있다. 실력 보상이 누적 플레이만으로 대체된다.
3. `runKills`·`runSurvivalSeconds`·`runGold`는 런 종료 평가에서만 쓰인다. 무기 모달은 한 판 조건의 현재 진행도를 표시할 수 없어 목표만 보여 준다.
4. `playerRecords`에는 `totalPickups`, `weaponMasterCount`가 정의되어 있지만 현재 누적시키는 호출이 없다. 해금 조건으로 쓰면 영구히 달성되지 않는 죽은 조건이 된다.
5. 하나코·바이키티 커터칼·선긋기는 의도적으로 계정 해금이 아닌 런 중 조합 카드다. 이를 일반 잠금 무기로 바꾸면 최근 적용된 `치비코 → 하나코`, `커터칼 → 바이키티` 1회 보장 규칙과 충돌한다.
6. 현 STARTER 13종을 단순히 잠금으로 바꾸면 과거 유저의 사용 가능 권리가 사라진다. 현재 STARTER는 Firebase `weaponUnlocks`에 저장되지 않으므로 선행 권리 이전 없이는 회귀가 난다.

## 추천 해금 체계

### 1) 기본군: 첫 판에서 선택 가능한 4종

|무기|추천 계정 상태|런 중 카드|
|---|---|---|
|연필|기본 장착|Lv.1부터|
|30cm 자|기본 해금|Lv.2부터|
|커터칼|기본 해금|Lv.2부터|
|텀블러|기본 해금|Lv.2부터|

첫 런은 연필만 들고 시작하되, Lv.2부터 근접/궤도체라는 서로 다른 선택을 제공한다. 기본군을 4종으로 제한해 처음부터 13종의 낯선 카드가 섞이지 않게 한다.

### 4) 무기 조합 해금군

|무기|추천 계정 상태|런 중 조건|현재 보장 규칙|
|---|---|---|---|
|하나코|계정 잠금 없음|치비코 보유|치비코 획득 후 다음 가능한 레벨업에 1회 확정|
|바이키티 커터칼|계정 잠금 없음|커터칼 보유, Lv.6 이상|커터칼 획득 후 조건 충족 첫 레벨업에 1회 확정|
|선긋기|계정 잠금 없음|30cm 자와 커터칼 보유, Lv.8 이상|현재 확정 보장 없음|

조합 무기는 계정 도감에서 “조합 발견”으로 별도 표시만 하고, 영구 해금으로 바꾸지 않는다. 그래야 한 런의 무기 조합 자체가 빌드 목표가 된다.

## 해금 보상 속도

|구간|권장 도달 보상|목표|
|---|---|---|
|첫 3런|과학 플라스크, 오리요강, 치비코 + 첫 Stage 1/보스 성공 시 벨 또는 보조배터리 미사일|매 판 새로운 전투 방식이 최소 1개 보이게 함|
|4~10런|우산 방어막, 오니기리, 지우개 폭탄, Stage 2 보상 2종, 이누콘|클리어·생존·코인·처치의 서로 다른 행동을 보상|
|장기|학생용 랜턴, 스타링크, 조합 3종 숙련|무작정 런 수만 쌓지 않고 더 높은 스테이지/빌드에 도전하게 함|

동시에 여러 조건을 달성하면 해당 무기를 모두 해금하되, 결과 화면의 신규 해금 목록은 획득 순서를 **기본군 제외 → 누적 → 스테이지/보스**로 고정한다. 하나의 무기는 한 번만 지급하며, 이미 Firebase `weaponUnlocks[id] === 1`이면 재보상하지 않는다.

## 기존 유저 보호 및 전환

1. 배포 전에 현 STARTER 13종(`연필, 30cm 자, 커터칼, 텀블러, 과학 플라스크, 벨, 전기, 오니기리, 치비코, 하나코, 이누콘, 바이키티 커터칼, 선긋기`)의 **기존 계정 권리**를 Firebase `weaponUnlocks`에 1회 이전한다.
2. 이전 전용 `legacyWeaponUnlockMigrationVersion`을 Firebase progress에 기록한다. 신규 계정 생성 시에는 현 버전을 즉시 기록해, 신규 계정이 이전 혜택을 받지 않게 한다.
3. 이전은 합집합만 수행한다. 기존 `weaponUnlocks`와 기존 권리를 덮어쓰거나 삭제하지 않는다.
4. 카탈로그에서 STARTER를 축소하는 변경은 위 이전 코드와 신규 계정 버전 기록이 먼저 배포된 뒤에만 한다. 두 단계를 같은 배포에서 순서 없이 섞지 않는다.
5. 조합 3종은 과거에도 계정 해금 게이트를 우회했으므로 권리 이전 대상에서 제외해도 플레이 가능하다. 단, 도감에 영구 해금 수로 표시할지 여부는 아래 확정 사항에서 결정한다.

## 구현 단계와 수용 기준

1. **진행 데이터**: Firebase progress에 해금 체계 버전과 기존 유저 1회 이전을 추가한다. 기존 unlock map은 합집합만 허용한다.
2. **카탈로그**: 위 추천 조건으로 `unlockConditions`와 STARTER 기본군을 갱신한다. OR 규칙을 유지하므로 각 계정 무기는 단일 조건으로 선언한다.
3. **카드 선택**: `upgrades.js`의 런 중 `minLevel`, 하나코/바이키티/선긋기 선행 무기 조건 및 최근 1회 보장 규칙을 유지한다.
4. **도감/UI**: 계정 해금, 런 중 조합, 다음 목표를 구분해 표시한다. 한 판 조건을 계정 영구 진행 막대로 오인하게 표시하지 않는다.
5. **테스트**: 새 계정 첫 런, 기존 계정 이전, 각 누적 조건 경계값, Stage/Boss 조건, 세 조합 카드, 중복 해금 무보상, Firebase 재로그인 복원을 검증한다.

수용 기준은 다음과 같다.

- 새 계정은 연필 시작과 기본군 4종만 계정 해금 상태다.
- 추천 조건의 정확한 경계값에서만 해당 계정 무기가 해금되고, 다음 런의 레벨업 카드 후보가 된다.
- 하나코·바이키티·선긋기는 계정 조건과 무관하게 해당 런의 선행 무기가 없으면 나타나지 않는다.
- 기존 유저는 배포 전 사용 가능했던 무기를 하나도 잃지 않는다.
- 해금은 Firebase 진행 데이터에만 저장되고, 새 세션에서도 동일하게 복원된다.
