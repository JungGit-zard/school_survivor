탈출 좀비학교 무비용 개발자 마케팅 실행안

기준일 2026년 10월 14일 · 1인 개발자 Terry · 현금 지출 0원

개발 과정을 공개하고, 작은 커뮤니티에서 한 가지 질문으로 플레이를 부탁하고, 받은 의견에 답한 뒤 실제 반영 내용을 공개한다. 처음 온 사람이 다음 변경을 확인하러 돌아오고, 재미를 느낀 사람이 자발적으로 공유하도록 이 흐름을 반복한다. 비용 대신 기존 자산과 하루 30분의 개발자 시간을 사용한다.

목표는 조회수 확대보다 첫 판 시작 → 첫 판 60초 생존 → 두 번째 판 → 다음 날과 7일 뒤 재방문이다. 60초는 첫인상을 부탁하는 기준이며 별도 게임 모드가 아니다. 이 문서는 실행 설계이며 실제 게시·발송·게임 수정은 별도 행동이다.

1 게임과 첫 번째 부탁

탈출! 좀비학교는 학교에서 몰려오는 좀비를 피하면서 자동 공격과 레벨업 카드로 성장하고 탈출을 노리는 생존 액션이다. 연필·자·텀블러 같은 생활용품 무기와 친구의 부탁이 처음 소개할 소재다. 기능을 전부 나열하기보다 한 장면과 한 질문으로 시작한다.

첫 부탁: “연필로 좀비학교에서 첫 판 60초만 버텨 주세요. 처음 조작과 목표를 이해했는지 한 줄만 부탁드립니다.”

알려 줄 사실표현
가격무료이며 게임 내 광고와 유료 구매가 없다.
시작 조건설치 없이 브라우저에서 플레이하며 시작 전 Google 로그인이 필요하다.
조작이동으로 피하고 공격은 자동이다. 레벨업 때 카드를 선택한다.
첫 플레이 목표60초는 테스트 부탁의 기준이다. 전용 모드·클리어 시간·보상으로 약속하지 않는다.
현재 검토 사항3개 랭킹 탭과 누적랭킹 기본 선택, 0점 기록 요청은 미배포다. 현재 제공되는 기능으로 소개하지 않는다.

웹 플레이를 첫 링크로 둔다. 게임 소개는 상세 설명을 원할 때 보조로 쓴다. “무가입”, “로그인 없이 즉시 시작”은 사용하지 않는다. 기존 가이드의 게스트 설명보다 현재 확인된 Google 로그인 필요 조건을 따른다.

Android는 프로젝트에서 확인된 Google Play 주소만 보조 링크로 사용한다. 공개 트랙과 이용 가능 국가 확인 전 누구나 설치 가능하다고 약속하지 않는다.

2 개발자가 반복할 운영 흐름

단계실제 행동다음 단계로 이어지는 이유
개발일지현재 게임의 장면 하나와 고민 하나를 공개한다.무엇을 만들고 있는지 이해한 사람이 테스트를 선택한다.
소수 테스트조건을 충족한 커뮤니티 한 곳에서 질문 하나로 첫 판을 부탁한다.답할 부담을 줄이고 실제 플레이 경험을 받는다.
의견 정리조작 혼란·재미·문제를 구분하고 재현 조건을 확인한다.막연한 호불호를 다음 작업의 근거로 바꾼다.
작은 개선 결정영향이 큰 문제 하나를 별도 개발 과제로 제안한다.요청 범위와 검증을 거쳐 실제 개선할 대상을 좁힌다.
업데이트 공개반영이 끝난 항목만 전후 장면과 함께 공개한다.전에 의견을 준 사람이 결과를 확인할 이유가 생긴다.
재방문과 공유원할 때만 다시 해 보도록 부탁하고 공식 링크를 제공한다.재방문을 강요하지 않고 경험에서 나온 자발적 공유를 만든다.

이 흐름의 중심은 관계와 응답이다. 게시글 수를 늘리는 것보다 “의견을 읽었고 무엇을 할지 결정했다”는 답을 남긴다. 아직 반영하지 못했다면 예정 또는 보류로 표시한다. 후기·추천·친구 초대를 참여 조건으로 요구하지 않는다.

3 누구에게 어떤 글을 어디에 쓰는가

채널과 대상글과 소재운영 빈도재방문 연결
기존 Tistory 독자와 검색 이용자실제 개발 문제 하나, 해결 과정, 스크린샷, 끝에 플레이 링크개발 내용이 있을 때 주 1편을 작업 기준으로 한다.같은 글에 결과를 갱신하고 다음 개발일지로 연결한다.
자격을 충족한 국내 개발 커뮤니티개발 참여를 밝힌 테스트 요청, 실제 장면, 질문 1개첫 주 허용된 곳 1곳에 1건. 이후 규칙과 실제 변경을 기준으로 한다.원글 댓글로 결과를 알리고 완료된 개선을 연결한다.
r/playmygame의 무료 게임 테스터개발자 역할·무료 조건·로그인 필요·직접 링크가 있는 영어 글동일 게임 재게시까지 1개월 이상. 기존 계정 게시일을 먼저 확인한다.피드백에 답하고 원글에서 업데이트 소식을 알린다.
인디터 회원게시판 규칙을 확인한 뒤 개발일지 또는 테스트 글등급·허용 간격 확인 전 미정이다.허용된 원글·댓글로 후속 소식을 전한다.
itch.io 이용자무료 개발 소개와 devlog, 실제 장면과 공식 웹 링크등록 조건을 통과한 뒤 의미 있는 변경 때 갱신한다.새 devlog에서 전후 결과와 플레이 링크를 제공한다.
공개 테스트 모집을 연 크리에이터모집 조건에 맞는 자발적 참여 신청현재 모집과 웹게임·로그인 조건이 맞을 때 1회 신청한다.신청 결과를 존중하고 답변 요구나 반복 연락을 하지 않는다.

생존 액션을 좋아하는 일반 플레이어와 개발자는 별도 집단으로 기록한다. 개발자는 문제 설명에 도움을 주고, 일반 플레이어는 실제 재미와 다시 할 이유를 보여 준다. 기존 X·Facebook 자동 예약은 그대로 유지하며 이 계획으로 중복 등록하거나 비활성화하지 않는다.

4 지금 쓸 채널과 조건을 확인할 후보

공개 규칙 확인일은 2026년 10월 14일이다. 무료 채널이라는 사실과 현재 계정이 게시할 자격이 있다는 사실은 다르다.

구분과 주소확인된 조건실행
기존 Tistory 운영 계정기존 원고 자산은 있다. 실제 공개 글 주소는 확인해 기록한다.본인 게시 권한과 공개 주소가 확인되면 일지와 플레이 링크를 운영한다.
디시 인디 게임 개발 갤러리2026년 10월 6일 공지는 홍보·테스트 글에 일지탭 글 5개 이상을 전제로 한다. 홍보탭은 HIT탭과 통합되었다고 안내한다.계정의 기존 일지 5개 확인 전 테스트 모집을 보류한다. 실제 과정이 없는 분량 채우기나 도배는 하지 않는다.
r/playmygame무료로 지금 플레이 가능, 직접 링크, 게임 설명과 개발 참여, 사실에 맞는 표현, 동일 게임 1개월 재게시 간격이다. NDA 게임 금지, 공포 성격의 NSFW 표기 규칙도 있다.Google 로그인 필요를 공개한다. 규칙 JSON에 계정 요구 허용 여부는 명시되지 않아 고정글·작성 양식·운영 판단을 추가 확인한다.
인디터본문 접근 오류로 현재 홍보 게시판·등급·빈도는 미확인이다.로그인한 계정에서 공지와 게시판을 읽은 뒤 선택한다.
itch.io등록·검색 노출·iframe 인증은 서로 다른 조건이다.§9 조건을 검토한 뒤 등록 후보로 판단한다.

국내 개발갤은 최신 공지의 일지 5개 조건을 우선 확인하고 기본 규칙도 읽는다. Reddit는 공식 규칙 JSON을 근거로 하며, 게시 직전 현재 고정글과 계정의 마지막 게시일을 확인한다. 국내 웹게임 포털에 개발자 접수 규칙이 없으면 게시 가능한 곳으로 추정하지 않는다.

채널 기록은 게시판 / 계정 자격 / 공지 URL / 확인 시각 / 마지막 게시일 / 다음 허용일 / 원글 URL로 남긴다. 삭제된 글을 곧바로 재게시하지 않는다.

5 스크린샷과 GIF로 재미를 보여 주기

기존 자산과 실제 게임 장면만 사용한다. 스크린샷은 장면 하나를 이해시키고, GIF는 연속 움직임이 설명에 꼭 필요할 때만 짧게 붙인다. 새 유료 도구를 설치하지 않고 기존 캡처·편집 도구를 사용한다.

장면보여 줄 것붙일 질문
연필 공격과 회피학교에서 학용품으로 버티는 첫인상처음 보고 무엇을 해야 하는지 알았나요?
텀블러 등 무기 행동생활용품이 전투 도구가 되는 재미이 무기를 다시 써 보고 싶었나요?
카드 선택 전후선택이 공격이나 플레이에 미친 실제 변화카드를 고를 때 설명이 충분했나요?
친구의 부탁생존 중 다른 행동을 선택하는 상황부탁을 따라가고 싶었나요, 지나쳤나요?

게시글에는 첫 장면 1개를 중심으로 두고 필요하면 보조 이미지 1~2개를 붙인다. GIF만 올리지 말고 개발자 역할·게임 설명·직접 링크·질문을 본문에 쓴다. 첫 화면과 UI를 바꾸어 홍보 장면을 만들지 않는다. 이메일 등 개인 정보가 보이는 로그인 화면은 소재에서 제외한다.

Graphic_designer/blog_tistory_20261011/tistory_body.html과 title.txt에는 기존 소개와 질문이 있다. 콘셉트 이미지의 “실제 게임 화면이 아닙니다” 표기를 유지한다. Planner/escape_zombie_school_complete_guide_20261011.html은 내부 설명 참고다. 로컬 가이드의 무기·퀘스트 갯수나 등장 시각을 실제 배포 검증 없이 새 약속으로 내세우지 않는다.

6 검색되는 개발일지와 문제 해결 글

개발일지는 단순히 “만들었습니다”를 반복하는 글보다 한 문제와 결과를 보여 주는 글로 쓴다. 게임을 찾는 사람이 읽을 수 있는 제목과 개발자가 찾는 문제 설명을 함께 둔다. 첫 문단과 끝에 플레이 링크를 하나씩 배치하고 시작 전 Google 로그인을 안내한다.

제목 후보는 “무료 웹게임 탈출 좀비학교 첫 플레이 방법”, “연필 무기를 처음 본 사람이 조작을 이해했는지 테스트하기”, “탈출 좀비학교 카드 선택 설명을 점검한 과정”이다. 해결하지 않은 문제에는 “해결”이라고 붙이지 않는다. 검색 노출 시점과 상위 노출을 보장하지 않는다.

9 무료 개발 페이지와 공개 모집 참여

itch.io는 무료 개발 페이지와 devlog 후보지만, 소개 등록·검색 노출·게임 실행 호환성은 각각 검토한다. HTML5 공식 안내는 브라우저 게임이 iframe 안에서 실행되며 ZIP 루트에 index.html이 필요하다고 설명한다. 현재 게임의 Google/Firebase 로그인은 팝업·리디렉션·허용 도메인·쿠키 조건과 함께 실제 호환성 확인이 필요하다.

itch.io 품질 가이드는 방해되는 광고와 제3자 로그인을 피하도록 안내한다. 이는 단순 업로드 파일 형식과 다른 품질·노출 검토 조건이다. 게임 내 광고가 없더라도 Google 로그인이 필요하므로 등록·노출에 적합하다고 단정하지 않는다. 공개 devlog는 게임 파일을 업로드하지 않아도 검색 등록이 가능하다. 우선 무료 개발일지 공개를 검토하고, 작품 페이지의 검색 등록과 브라우저 게임 배포는 따로 판단한다. 작품 페이지 검색 등록에는 다운로드 또는 브라우저 플레이 같은 제공 조건이 있다. 로그인벽을 피하라는 안내는 필요한 경우를 인정하는 권고이며 절대 금지로 해석하지 않는다. 검색 등록 안내도 함께 적용한다. 새 기능·업데이트 devlog는 플랫폼의 이메일 요약에 포함될 수 있지만 발송·수신을 보장하지 않는다. 커뮤니티 홍보는 지정된 Release announcements 게시판의 현재 규칙을 확인하고 다른 게임의 댓글에 링크를 남기지 않는다. 인증이나 iframe 코드를 임의 수정해 등록을 밀어붙이지 않는다.
