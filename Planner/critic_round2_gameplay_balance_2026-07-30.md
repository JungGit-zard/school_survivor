## 판정

**종합 6.2 / 10 — FAIL (8.0 이상 아님).**

1차의 가장 큰 구조 결함은 해소됐다. Stage 1은 기획·설정·버스트·런타임에서 모두 240초 생존 후 포탈 진입으로 끝나고, B01은 186초 경고·192초 등장·별도 보너스 성취가 됐다. 보스를 잡아도 결과 화면으로 나가지 않으며, 포탈이 런 종료와 점수 확정을 맡는다.

그러나 이 게임이 실제로 4분 동안 재미있고 공정한지는 아직 증명되지 않았다. **0:00~240초 정상 성공 3회와 실패 3회**, B01 처치부터 포탈 진입·결과까지의 실제 흐름, 192/240초 보상 각각 1회, 각 사건 뒤 HUD의 다음 목표를 반복 관찰한 근거가 없다. 따라서 코드 정합만으로 8점 통과를 주지 않는다.

## 1차 대비 확인된 개선

1. **완료 조건 단일화**: `Planner/current_game_rules.md`가 Stage 1=240초, 포탈 진입 클리어, HP 0 게임오버를 명시한다. `stageConfig.js`도 동일하게 240초/186초/192초를 둔다.
2. **보스의 역할 정리**: B01 처치는 `recordBossDefeat()`로 사실과 징글만 기록하고, 결과 전환은 포탈의 `clearStageAndStartNext()` 경로만 수행한다. 미클리어 보스 보너스는 랭킹 점수에서 무시된다.
3. **후반 이벤트를 구조상 도달 가능하게 수정**: 보상은 48/144/192/240초에 각각 정의돼 있고, 240초 포탈은 실제 E2E 런의 256초 캡처에서 관찰됐다.
4. **마틸다 읽기 시간 보장 계약**: 180초 트리거 뒤 4.5초 게임 시간 동안 AI 생성을 미루고 pause/level-up에서는 시간을 소모하지 않게 했다. 단, 수정 후 실제 장면은 없다.
5. **프레임 계약 정리**: 게임 시간·무기/적·플레이어·포탈 흡입이 1/60초 fixed-step과 최대 0.5초 raw-delta 제한을 공유하도록 수정했다.

## 남은 문제

### P0 — 정상 조건의 6회 4분 플레이 증거 부재

- 영향: 밸런스라는 핵심 질문(누가 어느 구간에서 왜 죽고, 무엇을 골라서 버티는가)에 답할 수 없다.
- 최소 작업: 동일 빌드에서 성공 3회와 실패 3회를 실제 조작으로 기록한다. 각 런에는 시작, 첫 레벨업, 144초, 마틸다/보스, 192초 보상, 240초 포탈, 결과 또는 사망을 남긴다.
- 로그 항목: run ID, 정상/개발 오버라이드 여부, 무기·업그레이드 선택, 레벨, HP, 사망/클리어 시각과 원인, 보스 처치 시각, 각 마일스톤 골드, 포탈 진입/결과 점수.

### P1 — 포탈 클리어와 보스 보너스의 실사용 흐름 미증명

- 영향: 코드상으로는 정합이지만, 플레이어가 B01을 잡은 뒤 240초에 포탈을 인지·도달·완료하는 흐름과 결과 화면 점수가 실제로 닫히지 않았다.
- 최소 작업: B01을 처치한 정상 런 1회에서 192초 보상, 240초 보상, 포탈 흡입, `STAGE CLEAR`, 보스 보너스, 결과 행동을 연속 영상/로그로 남긴다. B01을 못 잡은 정상 런 1회도 포탈 클리어하여 보스 생존 여부와 포탈 완료 조건의 관계를 대조한다.

### P1 — HUD의 “다음 목표”가 사건별로 지속적으로 전달되는지 미증명

- 영향: 포털 등장 순간의 “탈출구가 나타났다!”만으로는 보스 직전, 마틸다 대사 직후, 보상 후에 무엇을 해야 하는지 충분히 알 수 없다.
- 최소 작업: 위 6회 영상의 타임코드별 HUD 판독 체크를 추가한다. 보스 경고(186), 보스(192), 포탈(240), 결과에서 다음 행동을 1초 이내 읽을 수 있는지 기록한다. 읽히지 않는 지점이 확인된 뒤에만 카피/표시를 최소 수정한다.

### P2 — 밸런스 계측값 부재

- 영향: WAVE `17→34→11→17` 의도와 실제 체감(초반 학습, 168~192 압박, 보스 집중 완화, 포탈 스프린트)이 연결됐는지 알 수 없다.
- 최소 작업: 6회에서 40/96/144/168/192/224/240초의 HP·레벨·무기 수·활성 적 수·사망 원인을 표로 만들어, 수정 전후 또는 목표 난이도와 비교한다. 데이터가 나온 다음에만 적 수치·드랍·무기를 조정한다.

## 8점 도달을 위한 최소 다음 검증 묶음

1. 개발 오버라이드를 제거한 동일 빌드에서 0~240초 성공 3회/실패 3회를 실행하고, 실패 2종 이상(포위, 보스/돌진 등)을 포함한다.
2. 성공 3회 중 최소 1회는 B01 처치 후 포탈, 최소 1회는 B01 미처치 상태에서 포탈을 완료해 **포탈만이 클리어**임을 실사용으로 확인한다.
3. 6회 모두에서 192초·240초 보상 1회, HUD 다음 목표, 결과 시간·보스 보너스를 기록한다.
4. 최소 1회는 390×844 실제 터치, 최소 1회는 데스크톱에서 실행하며, 일반 HP 조건의 모바일 혼전·레벨업·pause/resume·결과를 수동 확인한다.
5. 결과 표를 `Planner/`와 `Quaility_Assurance/`에 분리 기록한 뒤, 그 데이터로만 난이도 수치 변경 여부를 판정한다.

## 최종 결론

구조적 불일치는 **5.2에서 6.2로 유의미하게 개선**됐다. 하지만 “4분 생존형 캐주얼 게임이 실제로 반복해서 공정하고 재미있다”는 비평은 아직 코드 정합 단계에 머물러 있다. 위 직접 검증 묶음 전까지는 **6.2 / 10, FAIL**이 현재 증거에 맞는 점수다.
